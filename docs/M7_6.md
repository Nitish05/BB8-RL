# M7.6: scan memory and fast multi-camera observation

Historical milestone report. [M7.8](M7_8.md) adds scan-memory driving, and
[M7.9](M7_9_VALIDATION.md) connects multi-camera fusion to interactive navigation.

Both tracks now have executable implementations and measured experiments. BB8-RL
remains separate from Genesis Studio. No SAC weights, actuation code or existing
single-camera controller were changed. The new modules produce observations,
estimated geometry and replay diagnostics; they do not authorize blind motion.

## A. Scan once, then fix the camera

The experiment uses the existing 24 translated RGB scan views of the static authored
room. Synthetic intrinsics and metric OpenCV camera poses are supplied explicitly.
Views 0–22 may build the map; view 23 is reserved as the final-perch registration
query. Its RGB and intrinsics may enter registration, but its pose enters only the
subsequent scorer. No renderer depth, segmentation or obstacle dimensions enter
reconstruction or camera registration.

`mapping.scan_geometry` implements a classical comparison: mutual SIFT ratio
matching, calibrated epipolar checks, tracks spanning at least three views, DLT
triangulation, positive-depth/reprojection/acute-parallax rejection and PnP camera
registration. Repeated descriptors of a landmark do not defeat the ratio test's
distinct-landmark requirement. Sparse surfaces never imply observed free volume.
The initial 23-view run produced 156 landmarks and rejected the query registration.

`mapping.backends.mapanything` loads the [official Apache checkpoint](https://huggingface.co/facebook/map-anything-apache)
through the [official MapAnything implementation](https://github.com/facebookresearch/map-anything)
in a separate optional runtime. It preserves predicted optical-Z, masks, uncalibrated
confidence, processed RGB/K, supplied and predicted camera poses, and metric point
cloud variants. Initial inference succeeded on four and eight views. Joint 23-view
FP32 attention exceeded the local MPS allocation limit; the failure is retained.
The bounded batch experiment retained 16 unique views (0–12, 15, 18, 21).
Windows 10–17 and 15–22 collapsed to degenerate predicted geometry and failed
camera alignment. Their raw arrays/failure records remain available; the merged
map excludes them and reports missing views explicitly. It is a concatenation of
independent estimates, not a globally optimized or jointly inferred 23-view map.

Supplying calibration to the neural model does not enforce exact calibration. Its
eight-view estimated baselines were approximately 10% too small. An explicit
similarity fit from predicted scan-camera centers to supplied scan-camera centers
recovers a scale of 1.10557. This uses camera priors already available to the mapper,
not scene surfaces or the withheld query pose. Raw geometry is preserved beside
the pose-aligned model cloud and the scale-corrected depth reprojected through exact
supplied K/poses. Camera-fit residuals and independent surface errors remain visible;
a visually plausible point cloud is insufficient for navigation.

`register-scan-camera.py` samples valid, locally continuous estimated depth at SIFT
features and attempts pooled and per-map-view PnP using the held-out RGB. Candidate
selection uses reprojection/inlier and cross-view agreement criteria, never query
truth. Both the raw and scale-corrected eight-view maps produced 10,102 sampled
landmarks, but all pooled/per-view PnP candidates were rejected under unchanged
thresholds. Rejected registration remains rejected; a known synthetic query pose
cannot rescue the estimator.

`mapping.surface_memory` and `import-scan-memory.py` voxelize estimated elevated
surfaces, retain per-voxel source views and assumed uncertainty, and serialize the
existing `RoomMemory` contract. The source cloud preserves shape samples. The import
does not infer static object identity, complete unseen object backs, or certify
FREE cells. It can include the parked robot until transient-object handling is added.
Missing volume remains UNKNOWN, so these maps do not certify a driving corridor.

`evaluate-scan-geometry.py` is a separate scorer. It reads finished artifacts before
comparing against synthetic exposed floor and box surfaces, without fitting the map
to those surfaces. It reports precision and sampled obstacle completeness separately.
Geometry and final-camera errors must pass independent gates before memory enters
control.

In the corrected scorer, eight-view raw calibrated geometry had a 41.14 cm in-room
surface-distance p95. Camera-prior scale correction reduced that to 16.26 cm;
full model-cloud similarity alignment yielded 16.79 cm. These errors remain far
too large to use as BB-8 collision clearance. Sparse triangulation had 8.95 cm p95
but only 156 points, with almost no obstacle coverage. Precision alone cannot
establish completeness or certify unobserved volume.

The final 16-view concatenation contains 3,215,537 mask-valid samples. Its in-room
surface-distance median/p95 are 7.55/16.55 cm. Although 96.2–100% of each obstacle's
sampled exterior is within 5 cm of some reconstructed point, substantial erroneous
geometry remains: only 24.5% of in-room reconstructed samples are within 5 cm of a
true exposed surface. The memory import retains 428,341 elevated samples in 26,210
source voxels, with an explicitly assumed 5 cm import margin and zero FREE evidence.

## B. Fast multi-camera tracking

`LearnedObserver.observe_position` shares the exact head-localization computation
with full observation and skips floor inference/refinement and full robot-mask
construction. `PositionOnlyObserver` adapts it to `CameraView`. Its masks are immutable
all-false arrays, so faster tracking makes no new free-space claim. Mapping can run
at a separate cadence in a future controller.

`DeadlineCameraRig.process` starts its wall-clock budget before capture. It evaluates
against copied temporal state and commits that state only on time. Late results
contain neither fused nor per-view poses/masks and cannot refresh accepted history.
The wrapper requires stateless per-frame observers. It does not preempt inference
or issue a brake command; a future caller must consume its accepted flag and retain
an independent command watchdog.

Exact full/fast status, position and covariance parity passed on all 72 development
images and all 272 geometric-occlusion view frames. Fast fusion also matched all
136 recorded full-rig outputs, including source IDs and handovers.

An isolated native two-camera comparison, after eight warmup cycles per variant,
measured 40 cycles per variant. Full capture/inference/fusion took 72.42 ms median
and 80.90 ms p95, missing 50 ms in all 40 cycles. Fast observation plus the deadline
gate took 21.53 ms median and 29.26 ms p95, with 40/40 accepted and zero misses.
This measures a stationary scene with CPU localization and native rendering. It is
not a closed-loop 20 Hz guarantee. The third camera is supported but not promoted
by this two-camera timing experiment.

## Geometric occlusion and motion prediction

`probe-geometric-occlusion.py` creates two tall boxes and a clear central lane,
then issues a fixed command schedule through the ordinary Genesis actuator. Both
camera views undergo visible, one-hidden, both-hidden and reacquired phases. The
tall boxes are outside the training geometry. RGB is the observer input; renderer
head masks, physical positions and velocities are retained only for scoring.

All 136 requested observations and 270 commands were retained, with zero contacts.
Each camera had 57 fully hidden frames and zero hidden false accepts. Both were
hidden in 12 frames and fusion returned no pose in every one. Visible localization
p95 was 8.60 mm for A and 8.89 mm for B; sampled reappearance delays were 0.1 s and
0 s. There were three handovers. This was prescribed motion, not visual control.

`OcclusionBelief` compares the existing constant-velocity filter to a separate
constant-acceleration Kalman model. `replay-occlusion-belief.py` persists causal
estimates before reading scorer fields. Missing observations produce an explicitly
predicted state, do not update last-seen time, and expand an assumed uncertainty
envelope. Reacquisition residuals are recorded before correction. Commands are
retained as causal context, but these baselines are not command-conditioned models.

Hidden-position p95 errors for A/B/fused were 20.5/14.4/3.29 cm for constant velocity
and 399.6/59.3/4.43 cm for constant acceleration. Continuing acceleration through
long gaps failed badly. The large assumed covariance envelopes are not calibrated
safety guarantees. Neither prediction is passed to the controller.

## Reproduction and next acceptance work

Use the BB8 training interpreter for ordinary geometry, observer and replay tools.
MapAnything dependencies, source/checkpoint pins and its commands are retained in
[the isolated setup guide](M7_6_MAPANYTHING_SETUP.md); keep that runtime separate from the existing RL
environment. Use fresh output directories for all commands.

```bash
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/reconstruct-calibrated-scan.py --scan-dir /absolute/path/to/view-probe --output work/m76/classical-new
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/benchmark-fast-rig.py --mode offline --output work/m76/parity-new
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/benchmark-fast-rig.py --mode native --isolated --output work/m76/timing-new
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/probe-geometric-occlusion.py --output work/m76/occlusion-new
```

1. Improve scan geometry with denser overlapping captures, texture diversity and
   multi-view metric refinement. Test recovered dimensions, floor consistency and
   held-out final-camera registration before allowing map-derived clearance.
2. Identify a command-conditioned motion model from visible trajectories, validate
   uncertainty on held-out acceleration/braking/turning sequences, and compare it
   with the frozen CV baseline. Long occlusions must stop when uncertainty exceeds
   independently certified clearance.
3. Integrate fast tracking with slower map updates and an independent deadline/
   braking watchdog. First run visible two-camera trials; then brief occlusions
   with the whole predicted swept body and braking path inside certified free
   volume. Count every stop, collision, reacquisition failure and missed deadline.
4. Evaluate new room/camera seeds and scene changes. Add camera C only after its
   measured visibility benefit and full capture budget justify it. Scan-once maps
   must invalidate on detected scene or final-camera movement.

The evidence report records the exact artifact hashes, failed attempts and current
map/registration outcomes. A successful reconstruction job is not an arrival result.

Verification for this stage: 236 non-GUI tests passed (20 opt-in native tests
deselected), Ruff passed, and the new native timing and actual box-occlusion runs
completed. Existing SAC/vision checkpoint and actuator hashes are unchanged;
Genesis Studio remains clean.
