# M7.7 — Improve scan-once geometry and fixed-camera registration

Prepared 17 September 2026. This implements the follow-up to the M7.6 result:
16.55 cm p95 map error and failed final-camera registration. BB8-RL remains a
separate project using Genesis Studio.

## Result and scope

The original dense map now has **9.89 cm p95 surface error**, down from **16.55 cm**,
while retaining all 3,215,537 accepted samples. Median error falls from 7.55 to
1.67 cm. Mean completeness across the seven obstacles remains about 99% within
5 cm. The failed final-camera view now registers successfully, together with three
other reserved views: all four independently pass the fixed 5 cm / 1 degree gate,
with **4.87–8.68 mm position error**.

A separate RGB photometric reconstruction trades coverage for precision. Its
depth is supported by agreement between multiple images, rather than only by a
learned prior. It is stored and scored separately so missing surfaces cannot be
hidden by a favorable error percentile. Planar completion is an explicit,
bounded interpolation experiment, not a claim that arbitrary objects are planar.

These are offline results from the same synthetic room and original rendered
scan. The camera poses used during scanning are known metric inputs. The final
camera's pose is estimated from its RGB and intrinsics. This does not yet solve
uncalibrated handheld scanning, establish real-room performance, or validate
motion through occlusion. No navigation success rate is inferred from these
geometry results; the previous camera-driving pilot remains 8/12 arrivals.

## Frozen evaluation and work split

Three agents worked on learned registration, depth calibration/runtime diagnosis,
and independent scoring. The root implemented multiview photometric refinement,
reviewed integration and packaged the resulting evidence. The registration agent
then implemented the bounded planar-completion experiment.

Before reconstruction/refinement, views **14, 17, 20 and 23** were excluded from
all mapping RGB, camera-pose inputs, tracks and upstream model batches. The
successful M7.6 eight- and sixteen-view MapAnything artifacts satisfy this split.
The old classical map did not, so it was rebuilt rather than reused. View 23 was
already a development failure; views 14/17/20 are newly scored queries from the
same scan. This is not a new-room test set.

`work/m77/audit/protocol.json` freezes input hashes, surface definitions and
registration gates. The scorer reads simulator geometry and query poses only
after producer artifacts are frozen. Estimators never receive the boxes, renderer
depth, segmentation labels or withheld camera poses. Geometry precision is paired
with equal-object completeness and spatial support. All four registration queries
stay in the denominator, including rejection or failure.

## Registration: repair the correspondences

The new matcher uses native-resolution SuperPoint features and LightGlue pairs,
known-pose epipolar filtering, tracks with at least three views, two-degree
parallax and at most two pixels of reprojection error. A query keypoint must
associate with the same landmark through at least two mapping views. PnP keeps
the existing two-pixel and twelve-inlier requirements, then checks refinement,
positive depth and landmark spread. Query poses do not initialize PnP.

The metric map contains 414 RGB landmarks and is frozen before query matching.
The independent audit reports:

| Reserved camera | Accepted PnP inliers | Position error | Rotation error |
|---|---:|---:|---:|
| 14 | 133 | 7.348 mm | 0.05803° |
| 17 | 142 | 8.681 mm | 0.09410° |
| 20 | 142 | 4.874 mm | 0.04307° |
| 23, original final camera | 131 | 4.972 mm | 0.06882° |

The sparse landmarks themselves have 20.85 mm in-room p95 surface error but only
9.01% mean obstacle completeness. They are useful registration and calibration
anchors; they do not replace the dense room geometry.

This selection follows the [official LightGlue implementation](https://github.com/cvg/LightGlue)
and [ICCV paper](https://openaccess.thecvf.com/content/ICCV2023/html/Lindenberger_LightGlue_Local_Feature_Matching_at_Light_Speed_ICCV_2023_paper.html).
The source is pinned to `eb42fee2d71449efb0aa5c10549752b5d75384d8`.
LightGlue is Apache-2.0; the selected SuperPoint weights have a separate
[Magic Leap research license](https://github.com/magicleap/SuperPointPretrainedNetwork/blob/master/LICENSE).
Weights and optional dependencies stay outside the project's source archive.
The experiment README records weight hashes and the isolated environment.

## Dense geometry: correct bias without deleting points

The MapAnything preprocessing replay is bit-identical for the sixteen saved RGB
images, with matching processed intrinsics. Source camera metadata also matches
the actual renderer projection. There was no large calibration mismatch to fix.
A matched six-view CPU/MPS control agrees to 0.0072 mm p95 depth difference;
the earlier eight-view local-batch collapse is not established as an MPS bug.
Failed historical batches remain excluded and retained in the evidence.

Triangulated RGB landmarks supply independent metric optical-depth anchors.
Spatial deduplication keeps nearby landmarks in the same calibration/validation
role. Robust scale, affine-depth and affine-inverse-depth candidates are tested
globally, by source batch and by view; identity remains available. A candidate
must improve both median and p95 on the RGB validation observations. These
observations are reused for model selection, so their errors are validation
diagnostics rather than an unbiased final test.

The final fit uses 169 distinct usable landmarks and 591 depth observations,
including 126 validation observations. Validation median improves from 12.26 to
2.51 cm and p95 from 27.85 to 9.72 cm. Independent exposed-surface scoring then
finds the following, with the source masks and sample count unchanged:

| Metric | M7.6 dense 16 views | M7.7 RGB-calibrated 16 views |
|---|---:|---:|
| In-room median surface error | 7.55 cm | 1.67 cm |
| In-room p95 surface error | 16.55 cm | 9.89 cm |
| Accepted samples within 5 cm of a surface | 24.50% | 85.59% |
| Elevated-surface p95 error | 17.21 cm | 12.73 cm |
| Mean obstacle completeness within 5 cm | 98.79% | 99.11% |
| Least-complete obstacle within 5 cm | 96.20% | 93.95% |
| Accepted dense samples, including outside room | 3,215,537 | 3,215,537 |

Surface error measures distance from each estimate to exposed floor, wall and box
surfaces in the room. Completeness measures the fraction of independently sampled
exposed obstacle surfaces near an estimate, averaged equally over seven obstacles.
High completeness alone does not establish precision; the least-complete object
slightly worsens even as global error improves. Elevated residual error remains
too large to treat a nominal five-centimeter import margin as a proven bound.

## RGB photometric layer and planar interpolation

The depth search takes the calibrated learned depth as a prior and searches
±45 cm in 1.5 cm optical-depth steps. Calibrated neighboring RGB images are warped
for each hypothesis. The best two of four neighboring views must support a
textured 5×5 normalized-correlation patch, cost at most 0.08, and a uniqueness gap
of at least 0.02 outside three adjacent bins. A quadratic sub-bin estimate refines
accepted minima. Unsupported, flat and ambiguous pixels remain unknown.

The implementation uses OpenCV pixel-center resize geometry, including the
quarter-pixel principal-point shift at half resolution. Bilinear prior sampling
requires valid support from every contributing pixel; full patches cannot cross
image boundaries. Unit tests reproduce the resize and masking errors fixed during
review. Earlier artifacts remain explicitly labeled ablations.

The final sixteen-view photometric layer retains **344,414 / 1,466,746 eligible
prior pixels (23.48%)**. Its in-room p95 is **2.49 cm**, elevated p95 **4.87 cm**,
and 99.20% of estimated in-room samples lie within 5 cm of a true surface.
Mean obstacle completeness is **59.35%**, with a 48.85% least-complete obstacle.
This is a high-precision partial layer, not a replacement claiming the dense map's
99% coverage. At the same 226,852 retained in-room rays, calibrated-prior p95 is
8.87 cm and photometric p95 is 2.33 cm; 79.51% of rays improve. Thus the gain
includes depth correction, not just selection of already-good prior samples.

The separate eight-view experiment uses 4-connected RGB regions quantized into
32-level channel bins. It fits an inverse-depth plane on spatially separated
8-pixel tiles, requiring at least twenty fit and eight validation anchors, at most
1.5 cm validation median and 5 cm validation p95. Completion is restricted to the
same color component and exact convex hull of fitting anchors. Validation anchors
do not enter a final refit; the original photometric anchors remain unchanged.

| Eight-view experiment | Photometric anchors | Anchors + inferred planar points |
|---|---:|---:|
| In-room p95 | 2.49 cm | 1.80 cm |
| Elevated-surface p95 | 4.37 cm | 6.61 cm |
| Mean obstacle completeness within 5 cm | 55.33% | 61.90% |
| Accepted samples | 186,605 | 457,126 |

The interpolation adds 270,521 points, mostly floor. Completed elevated points
alone have 7.58 cm p95 and only 63.68% within 5 cm of truth. The favorable pooled
p95 therefore hides worse obstacle geometry. **Planar completion remains an
inferred experimental layer and is excluded from the delivered obstacle
memories.** The precise photometric layer and broader calibrated dense layer
remain separate. No parameters were retuned against the physical scorer.

## Artifacts and reproducibility

The source implements:

- `mapping/registration.py` and `scripts/refine-scan-registration.py` for learned
  map tracks and final-camera PnP;
- `mapping/depth_calibration.py` and `scripts/calibrate-scan-depth.py` for robust
  RGB-anchor depth correction;
- `mapping/photometric_refinement.py` and `scripts/refine-scan-photometric.py` for
  calibrated RGB depth search;
- `mapping/planar_completion.py` and `scripts/complete-scan-planes.py` for the
  separately labeled interpolation experiment;
- `scripts/audit-refined-scan.py` for independent frozen scoring, complete mapping
  ancestry validation, paired-ray comparisons and separate completion layers.

The effective runtime is selected through `scripts/python.sh`. On this machine,
set `BB8_PYTHON` to the existing `.venv-dreamer/bin/python`,
`NUMBA_CACHE_DIR` to `work/m77/numba-cache`, and `PYTHONDONTWRITEBYTECODE=1`.
Learned registration runs in `work/m77/registration/venv`, and calibration's exact
preprocessing replay uses the isolated M7.6 MapAnything environment. The optional
environments and weights are not dependencies of simulation/package import.

Use a fresh output directory for each command; none overwrites previous evidence.
Representative commands from the repository root are:

```bash
# In the optional registration environment, with its pinned source/weights present:
PYTHONPATH=src work/m77/registration/venv/bin/python scripts/refine-scan-registration.py \
  --runtime-root work/m77/registration --scan-dir SCAN_DIR --output NEW_REGISTRATION

# In the optional MapAnything environment, with its source on PYTHONPATH:
python scripts/calibrate-scan-depth.py --scan-dir SCAN_DIR \
  --reconstruction work/m76/mapanything/merged-valid-16/reconstruction.npz \
  --anchor-dir NEW_REGISTRATION --output NEW_CALIBRATION

./scripts/python.sh scripts/refine-scan-photometric.py --scan-dir SCAN_DIR \
  --prior NEW_CALIBRATION/reconstruction.npz \
  --prior-manifest NEW_CALIBRATION/manifest.json \
  --depth-field depth_z_rgb_calibrated_m --output NEW_PHOTOMETRIC

./scripts/python.sh scripts/audit-refined-scan.py score \
  --protocol work/m77/audit/protocol.json \
  --reconstruction NEW_PHOTOMETRIC/reconstruction.npz \
  --manifest NEW_PHOTOMETRIC/manifest.json --point-field points_world_refined \
  --prior-reconstruction NEW_CALIBRATION/reconstruction.npz --output NEW_AUDIT
```

The memory importer saves these as estimated occupied surface evidence. Missing
cells remain unknown; lower-than-four-centimeter points remain in the point cloud
but are not obstacles in memory. The imported five-centimeter margin is explicitly
an assumption, not calibrated uncertainty. The parked robot may appear in scan
surfaces; static object identity and change detection are not established.

The dense memory contains 159,081 elevated samples in 15,218 source voxels. The
photometric memory contains 32,826 samples in 2,702 source voxels. They have distinct
scene versions and remain separate; neither contains free-space evidence.

## Remaining acceptance work

Registration is repaired for this frozen synthetic scan. Dense geometry is
materially improved, but full precision, fresh-room generalization and blind
navigation remain separate gates:

1. Evaluate the same frozen pipeline on new randomized rooms and camera placements,
   reporting failures and per-obstacle coverage as well as distance percentiles.
2. Replace ideal scan poses with estimated or measured poses and evaluate scale,
   drift and final-camera relocalization jointly.
3. Separate static room surfaces from BB-8 and movable objects; detect changes and
   invalidate stale memory rather than treating every scan-time surface as static.
4. Add and validate explicit visible-free-volume evidence and calibrated error
   bounds. Missing reconstruction points must never become a free corridor.
5. Only then evaluate localization prediction and braking envelopes through native
   occlusion trajectories, before enabling scan-memory-based occluded driving.

No actuator, SAC weights, vision weights or Genesis Studio source changes are
required by this offline reconstruction work.
