# M7.5: multi-view observation and geometric memory

Historical milestone report. [M7.9](M7_9_VALIDATION.md) subsequently connects
these camera observations to guarded navigation and the interactive control room.

This stage adds observation and memory interfaces, native multi-camera capture,
floor retraining across camera angles and independent perception audits. The
single-camera driving controller is unchanged. Multi-camera route control, RGB
3D reconstruction and driving during full occlusion are not enabled.

## Camera runtime

`NavigationEnv(..., render_mode="rgb_array", camera_positions=[...])` creates
one to three fixed native camera objects before scene build. `world.cameras`
maps A/B/C to those objects; `world.camera` and automatic frame history retain
camera A. Rig users explicitly call `world.capture_rig()`. Returned RGB frames
share a paused simulation instant. Sequential render wall time is separate;
this does not imply hardware synchronization or 20 Hz wall-clock operation.

`calibration_from_live_camera` converts the current public camera transform to
OpenCV world-to-camera axes, avoiding cached extrinsics after movement. Real
cameras still require measured registration. A moved camera requires a new
calibration/version supplied by the caller.

Register `CameraView(camera_id, calibration_version, calibration, observer)`
objects in a `CameraRig`. `observe(frames, now=...)` returns measured position,
covariance, source IDs, per-view status and handover metadata. It rejects stale,
repeated, future, misregistered or malformed frames. Fresh ambiguous/inconsistent
identity evidence stops fusion. A fresh remaining camera can take over when
another disappears; missing output has no position.

Equal-weight covariance intersection avoids assuming independent camera errors.
Bounded motion inflates uncertainty for capture skew. These operations depend on
valid input uncertainties: detector covariance is currently heuristic and has not
been calibrated empirically. No free-space masks are fused by this module.

## Training and independent audit

`collect-multiview.py` generates independent rooms with varied boxes, lighting
and camera positions in A/B/C angle families. Each room/view is a sequence;
every view/reset from a room shares its split. Defaults: 24 training, 6 calibration
and 6 locked development rooms, four reset positions/view: 288/72/72 frames.
Held-out rooms use trained angle families with new perturbations. These are static
examples, not trajectories. Renderer labels/body positions are supervision only;
placement uses episode reset and zero-command settling. Every native image is hashed.

The manifest validator rejects crossed room/seed splits, missing camera members,
repeated paths and incomplete native frame references. `train-vision.py` uses all
four validation frames for this format. The initial run trained the floor network
from scratch with the old head frozen; its validation crop miss rate was 30%.
A second run adapted both networks and reduced that validation crop miss rate
to zero at the selected checkpoint. It was selected before the locked-room audit.
`--head-checkpoint` initializes only the head. The target is visible floor plus
self, keeping occluded background blocked.

`audit-multiview.py` selects a threshold on all native calibration frames using
the deployed guided filter (radius 4, epsilon 1e-4) and worst-camera weighted loss.
It freezes the checkpoint before reading locked rooms. Saved refinement is enforced
by the observer. Selection loss is not a driving gate. Audit output includes every
frame and per-view/per-room errors, network versus deployed floor/self masks,
localization failures, visible-head misses, hidden-head accepts and ambiguity.

```bash
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/collect-multiview.py --output work/m75/multiview-data
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/train-vision.py --dataset work/m75/multiview-data --output work/m75/vision --steps 1500 --device mps --floor-target traversable --head-checkpoint work/m72/calibrated-2/model.pt --freeze-head
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/train-vision.py --dataset work/m75/multiview-data --output work/m75/vision-joint --steps 1500 --device mps --floor-target traversable --head-checkpoint work/m72/calibrated-2/model.pt
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/audit-multiview.py --dataset work/m75/multiview-data --checkpoint work/m75/vision-joint/model.pt --output work/m75/calibrated
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" ./scripts/python.sh scripts/probe-camera-rig.py --checkpoint work/m75/calibrated/model.pt --output work/m75/rig-probe
```

Use fresh outputs. Native capture needs a working graphics context; MPS training
requires MPS explicitly. The rig probe generates prescribed motion and injects
stream loss. It does not steer from vision or test geometric occlusion control.
Physical route/backup clearance and map-contract gates remain required before
an added view authorizes simulated driving.

## Persistent memory

`mapping.RoomMemory` stores metric 3D bounds, voxel free/occupied/unknown evidence,
object bounds, source views, timestamps, provenance, uncertainty and registration
versions. JSON round trips rebuild cells from retained evidence. Free evidence
must cover full voxels after its uncertainty margin; occupied evidence overrides
free evidence and expands by its margin. Missing geometry never implies free space.

Segment queries cover the full robot-height bounding prism, conservatively rejecting
some clear diagonal paths. Scene or registration changes invalidate the map; the
caller must detect and report them. Object shapes are conservative axis-aligned
boxes in this first contract, not reconstructed meshes.

Six analytic scenarios cover visible space, remembered hidden space, never-observed
space, an ambiguous fork, changed obstacles and changed camera registration. These
test memory semantics only. No MapAnything inference, recovered scale, automatic
change detection or safe blind-driving duration is claimed. A geometry backend
must supply verified evidence before memory can support scan-based control.

All work remains in BB8-RL. Genesis Studio, SAC and the actuation adapter remain
unchanged, and simulation does not connect to hardware.

## Recorded first results

The selected calibrated checkpoint is
`483065dada5480f7ef990f526cec5f8a45c16438fb7931bcd1058d44ccd06ca8`.
On 72 locked-room images, every visible head was localized. Network false-free
rates were 0.068% / 0.051% / 0.472% for A/B/C, versus 0.156% / 8.625% / 13.290%
previously. All heads were visible, so hidden-head error remains unmeasured.
Static fused position p95 errors over 24 poses were 8.84 / 1.84 / 3.10 mm for
A / A+B / A+B+C under exact synthetic calibration.

The two-camera static route probe certified 11/12 original cases against both
visible truth and continuous physical clearance; case 007 lost its previous
route. These are not arrivals. A native prescribed-motion probe verified camera
stream handover and no reported position when both streams disappeared. Isolated
capture plus inference took 73.0 ms median / 118.9 ms p95, exceeding the 50 ms
20 Hz budget on all 15 two-view cycles. Faster tracking and deadline handling,
real geometric-occlusion cases and independent braking-path checks remain gates
before a two-camera closed-loop trial. The third camera remains unpromoted.

Verification: 164 non-GUI tests, Ruff, the native legacy frame-history test,
36 three-camera collection rooms and 25 analytic memory demo checks passed.
