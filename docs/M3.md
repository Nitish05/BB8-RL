# M3: synthetic oracle navigation

BB8-RL uses unchanged Genesis Studio 0.2.0 at `cd20c8c` to load and construct its
own worlds. Genesis World 1.3.2 integrates physics. This milestone implements the
navigation task, a classical controller and reproducible evaluation; it does not
train an RL policy or establish performance on the physical BB-8.

The task also supports `layout_mode: authored` for the
[synthetic M2 room](M2_SYNTHETIC.md). That mode reads fixed obstacle positions and
dimensions from the saved world. The original procedural benchmark below keeps
its eight parked cube slots and separate seed domains. Authored-room seed splits
vary endpoints, not geometry; use separately generated rooms for layout holdouts.

## Run

From the independent BB8-RL checkout:

```bash
./scripts/run-bb8.sh env-check --output work/gym-check.json
./scripts/run-bb8.sh evaluate --suite train --episodes 4 --controllers baseline --output work/train-pilot
./scripts/run-bb8.sh evaluate --suite validation --episodes 12 --controllers baseline random --output work/validation
./scripts/run-bb8.sh evaluate --suite train --episodes 1 --controllers baseline --viewer --output work/viewer-demo
```

`--backend metal` explicitly requests Metal; unsupported requests fail. CPU is the
default. Native GUI runs on the main thread. Evaluation is sequential with one
Genesis instance per process. Threaded/vectorized environments, training and
resume are not implemented. Existing output manifests are never overwritten.

The defaults live in `configs/navigation/bb8-task.yaml`, referencing
`bb8-navigation.yaml` and `projects/bb8/navigation.genesis.json`. These are files
in BB8-RL, not Studio configuration changes. The launcher can share Studio's Python
runtime or use BB8-RL's own `.venv`; the lock snapshot includes Gymnasium 1.3.0.

## Geometry and planning

The synthetic arena is 3 m square with physical walls. Eight fixed 30 cm cube slots
start parked outside it. Reset moves a subset into seeded empty, barrier, corridor
or scattered layouts and restores unused slots. Nonempty geometries vary by seed.
Additional interior colliders and floating/unparked obstacle slots are rejected
because they would disagree with the procedural map.

The grid uses 10 cm cells and inflates geometry by the 3.7 cm body radius plus an
11 cm provisional control clearance and half a cell diagonal for conservative
rasterization. Start and goal sampling checks footprint clearance, connectivity
and 0.6–2.5 m separation. Barrier/corridor cases cross from left to right.
Eight-neighbor A* rejects corner cutting; line-of-sight simplification rejects
segments grazing blocked cells. The bounded controller follows waypoints, slows
at corners and brakes at the goal through the existing force-based drive adapter.

The route controller has the **full oracle occupancy grid**. The environment's
observation contains a **local oracle map**. Random actions are a smoke comparison,
not a matched-information learning benchmark. A later learned local controller
should use the same global planner/waypoints for a fair controller comparison, or
explicitly report a different navigation problem.

## Environment contract

`bb8_rl.env.NavigationEnv` implements Gymnasium `reset`, `step`, `render`, `close`
and scalar/batched `compute_reward`. `reset(seed=..., options={"layout_seed": ...})`
reproduces a sampled case. Optional explicit `start` and `goal` must be supplied
together and pass route validation. Reset clears motion commands, actuator delay,
pose/velocity, contacts, history, clocks, success dwell and task termination state.
Physics state setters are used at reset only; normal motion uses bounded forces.

Actions are two finite values in [-1, 1], projected onto the unit disk, converted
by the drive adapter into speed and direction requests. Each action lasts ten
5 ms physics ticks (20 Hz). Contacts, boundaries and dwell are checked at every
physics tick. A numerical exception stops commands and requires reset.

The default dictionary observation is float32:

| Key | Shape | Meaning |
| --- | --- | --- |
| `observation` | 1353 | State, four command/velocity history rows, local map |
| `achieved_goal` | 3 | Current world x, y and planar speed |
| `desired_goal` | 3 | Target world x, y and speed zero |

The flat observation begins with x, y, vx, vy, uncertainty, age (six values).
Uncertainty and age are zero in oracle mode. Each of four history rows contains
vx, vy, requested x/y and applied x/y (24 values). The remaining 1323 values are
three 21×21 map channels in blocked/free/unknown order, flattened in C order.
Channels are exclusive; samples outside the world grid are unknown and never free.
No desired-goal value is baked into the ordinary observation.

Reward is -1 unless achieved and desired positions are within 10 cm and their
speeds within 3 cm/s, in which case the goal component is zero. Goal-independent
penalties from `info["event_penalty"]` remain after relabeling: collision 10,
boundary 10, plus optional squared-action cost (zero by default). Future-goal
relabeling compares achieved speed with the relabeled speed, not always zero.

**Arrival reporting requires 0.5 s continuously inside both tolerances.** Dwell is
an evaluation success metric, separate from the instantaneous sparse reward.
Success does not terminate the environment, so changing the desired goal does not
change stored terminal flags. Collision/boundary failures terminate; 600 actions
(30 simulated seconds) truncate. The evaluator stops on arrival and records it
explicitly. There is no autoreset, so terminal observations remain available.
If using SB3 HER later, preserve/copy info dictionaries so collision penalties are
retained, and handle time-limit truncation separately from true termination.

This follows the [Gymnasium environment contract](https://gymnasium.farama.org/api/env/)
and exposes the goal/reward interface required by
[SB3 HER](https://stable-baselines3.readthedocs.io/en/master/modules/her.html).
An actual HER trainer/checkpoint integration remains M4 work.

## Fixed evaluation and evidence

`configs/navigation/suites.json` defines disjoint layout-seed domains:

| Split | Allowed layout seeds | Fixed suite |
| --- | --- | --- |
| Train | 0–9999 | 12 cases beginning at layout 100 |
| Validation | 10000–19999 | 12 cases beginning at layout 10000 |
| Final test | 20000–29999 | 200 cases beginning at layout 20000 |

The final test performance suite is reserved for a frozen candidate. The split
separates seeds, not obstacle families; empty arenas necessarily share geometry.
Baseline and random runs receive identical layout/episode seeds and endpoints.
Random actions are independent uniform components every action tick followed by
unit-disk projection. They are a weak reference controller.

Every evaluation exports `manifest.json` (source/configuration hashes, dependency
versions, machine, devices and seeds), `episodes/*.json` (all outcomes, goals,
obstacles, trajectories and per-action timings), exact Studio worlds, `summary.json`,
`report.md` and `paths.png`. Cancelled/failed runs retain their status and completed
episode evidence. No hidden retries replace failed outcomes.

Reported statistics include success/collision rates with Wilson intervals, final
position error, path length, timeouts, arrival time for successes and p95 time to
choose an action and execute its physics ticks. Timing excludes scene setup and
initial A* planning; it is not camera/BLE/full-loop or training throughput. Path
efficiency uses the grid-planned route as an approximate reference and is capped
at one. A collision episode means any sampled non-floor body contact.

## Limits and next milestone

All geometry, masses and response parameters remain synthetic. There is no image
perception, moving-obstacle suite, external camera or BLE connection. Unknown-map
handling is represented in the contract; sensor dropout behavior is not validated
by perfect oracle observations. M2 now supplies a synthetic room and camera by
user choice; real room/camera/robot data are deferred to physical transfer.

[M4](M4.md) now supplies SAC + HER, learner-device checks, episode-boundary
checkpoint/resume and a three-seed pilot against this validation protocol. Its
reports record the information advantage given to the classical route planner. Reserve
the 200-case final test suite until model and hyperparameter selection are frozen.
