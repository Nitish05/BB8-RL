# M7.3 — camera boundary refinement and continuous endpoint clearance

This experiment follows the six failures in M7.2's 12-case camera development
pilot. The vision checkpoint and M6 SAC policy remain frozen. It investigates
pixel classification, map discretization and route following; it does not train
a new RL algorithm, use oracle observations, or establish physical reliability.

## Investigation and execution plan

1. Reproduce cases 000, 003, 007, 008, 009 and 011 with scoring-only renderer
   snapshots captured at the exact image/action state. Retain predicted floor,
   predicted self, visible ground/self truth, labels, estimated pose, calibration,
   route, map and action. Verify timestamp and image equality. Labels never enter
   the observer, planner or controller.
2. Compare the historical 5 cm, five-probe map with 2–2.5 cm maps that inspect all
   native pixels in each projected cell bounding rectangle. Inflate whole cells
   using rectangle-to-rectangle metric distance, retaining robot radius 3.7 cm,
   fixed margin 4 cm and three times the heuristic position sigma. Keep all
   unknown image regions blocked. Record regressions as well as improvements.
3. Test native RGB edge refinement with frozen floor probabilities. Use one
   representative snapshot from each of the eight existing validation scenes
   024–031. Compare guided-filter radii 2/4/8 pixels and epsilon 1e-4/1e-3 at the
   unchanged 0.5 threshold. Select by `20*false_free + 1-recall + 2*self_miss`
   before inspecting development-case effects. These eight snapshots are not
   independent new acceptance data.
4. Add continuous clearance checks against the predicted native mask. Project
   visible-region contours through the known floor homography, account for pixel
   geometry with a conservative global pixel-diameter margin, and reject unknown
   or insufficient-clearance endpoints. A* still uses the conservative grid.
   Exact endpoints may connect to nearby free cell centers only when the entire
   connector is certified. Never change occupancy, move the goal, or shrink
   requested inflation to make a route possible.
5. Check the next segment before advancing a nearby waypoint. A position within
   the waypoint tolerance can still be on the wrong side of an obstacle corner;
   advancing unconditionally caused repeated route invalidation.
6. Freeze the combined configuration: 2 cm metric grid, continuous connectors,
   validation-selected guided filter, existing learned checkpoints. Run all 12
   original native camera cases with synchronized audit snapshots, then a matched
   five-frame dropout case. Keep the distance <=10 cm, speed <=3 cm/s and dwell
   >=0.5 s arrival gate, 60-second episode budget and existing contact scoring.
7. Run non-GUI regression tests, record every attempted configuration, preserve
   executed source snapshots and report remaining visibility limits. Do not pool
   repeated development runs into a larger independent success denominator.

## Initial evidence and rejected configuration

The legacy rerun reproduced all six failures. Its saved audit images matched the
controller frames exactly; reconstruction of final maps reproduced every cell.
Case 008's sigma rose from about 6.68 to 8.69 mm, taking requested inflation from
9.704 to 10.306 cm. Rounding to 5 cm cells changed the old dilation radius from
10 to 15 cm. Case 011's exact goal also lies on a closed blocked-cell boundary.

The first 2 cm whole-cell metric run reached **5/12**, with zero collisions. It
recovered 011 but lost 005 and 006, and retained a corner-advance loop in 008.
Therefore finer grids alone were not an improvement over M7.2's 6/12. This run
used the old waypoint advancement and an unvectorized map conversion; its source
snapshot and timing results are retained separately from the combined candidate.

Visible-ground truth also reveals real observability limits. Case 009's clicked
goal is hidden by an obstacle from this camera. Cases 000 and 003 lack sufficient
visible clearance around an endpoint at the requested footprint and margin.
An oracle physical map can have a route even when a single image cannot certify
one. These scoring observations are not supplied to the runtime map.

## Selected RGB refinement

The filter is standard [guided image filtering by He, Sun and Tang (ECCV 2010)](https://people.csail.mit.edu/kaiming/eccv10/index.html), using normalized RGB
grayscale as guidance for native-resolution, bilinearly upsampled probabilities.
It is not a new foundation model or a novelty claim. The validation winner was
radius 4, epsilon 1e-4, with threshold unchanged at 0.5.

| Pooled pixels in eight validation snapshots | Bilinear | Guided |
| --- | ---: | ---: |
| Visible floor/self recall | 95.8617% | 98.3041% |
| False-free fraction of blocked pixels | 0.12204% (319) | 0.04093% (107) |
| Missed visible self pixels | 9/586 | 4/586 |

This improves this small synthetic validation sample; it does not guarantee that
refinement reduces every future segmentation error. The optional inference flag
defaults to `none` to preserve the historical baseline. No model weights change.

## Runtime semantics and limitations

`CameraClearance` uses the predicted visible-floor/self mask only. Contour parity
handles holes and nested visible islands. A full projected native pixel diameter
(about 19.50 mm for this camera) accounts conservatively for digital contour
geometry. Initial segment samples are at most 5 mm apart, with additional
clearance of half the actual sample gap using the distance function's
1-Lipschitz bound. Ambiguous intervals are bisected up to depth six or a gap of
0.1 mm; an unresolved interval rejects. Merely observing clear sample points
never establishes a clear segment without the interval bound.
Endpoint connectors are limited to 12 cm and every resulting route segment is
checked; failed searches request zero drive. Whole-cell maps are never modified.

The certificate is relative to the predicted mask and supplied calibration.
Misclassified free pixels, self-mask assumptions and inaccurate calibration can
still invalidate its relationship to physical geometry. Position covariance is
heuristic; three sigma is not a demonstrated probability guarantee. The map
assumes a static camera and static obstacles and is rebuilt on uncertainty/route
events. Inflation uses sigma at the last map rebuild; small subsequent sigma
changes within the existing replan threshold do not immediately change the map.
Dynamic scene change detection remains unimplemented.

The controller still uses RGB, capture time, known synthetic calibration, nominal
head height and a goal pixel. No renderer labels, oracle position, velocity, depth
or obstacle geometry cross this boundary. The native audit renderer is scoring
only and its time is excluded from controller/cycle latency and reported
separately. Simulation cadence does not establish real-camera wall-clock rate.

## Native combined results

The initial combined configuration reached **7/12**, with zero collisions,
four visibility aborts (000/003/007/009), and one timeout (006). It recovered
008 and 011 and retained 005. In 006, the frozen SAC policy settled 14.38 mm
short of a corner waypoint and the segment certificate prevented advancement.
The native trajectory distinguishes this stopped tracking state from loss of
camera localization or a collision.

Offline analysis found that the next segment had a small positive clearance
above the requested radius, but the uniform 5 mm sampling certificate demanded
up to 2.5 mm additional slack. The next corrective run adaptively subdivides
uncertain intervals while keeping the same radius, mask, pixel guard and
Lipschitz proof. Observed insufficient clearance still rejects immediately;
unresolved intervals at the finite subdivision bound still reject. This avoids
conflating conservative numerical approximation with insufficient visible space.

The adaptive run reached **8/12**, with **zero collisions**, four guarded
visibility/perception aborts and no timeouts. Successful cases were 001, 002,
004, 005, 006, 008, 010 and 011. Case 006 now arrived in 17.70 simulated seconds,
with final error 3.30 cm, speed 0.00696 m/s and dwell 0.510 seconds. Relative to
M7.2, all six previous successes were retained and 008/011 were recovered.

| Configuration | Arrivals | Visibility/route aborts | Timeouts | Collisions |

| M7.2 historical learned baseline | 6/12 | 6 | 0 | 0 |

These are repeated development scenarios in one authored synthetic room, not
independent trials, held-out camera acceptance or a controlled single-component
ablation. The combined candidate changes mapping, refinement and route handling.
The default CLI retains legacy/no-refinement options; the explicit command above
selects the evaluated configuration. Executed source snapshots preserve each
historical implementation, including the pre-fix waypoint behavior.

Cases 000 and 003 still lack enough visible endpoint clearance; 009's goal is
occluded. Case 007 is affected by segmentation boundary error and conservative
pixel/footprint treatment. None is silently removed from the denominator or
cleared from renderer truth. M6's 200/200 oracle-state result remains separate
evidence and is not evidence of camera reliability.

Across final cases, localization error p95 ranged 3.16–10.13 mm. In successful
episodes, observer/planner/policy p95 was 31.5–37.0 ms and the full
observer/physics/render cycle p95 was 49.5–55.8 ms, excluding scoring capture.
Repeated map rejection raised controller p95 to 119.7 ms in an abort case.
Scoring-only capture cost another 18.4–23.1 ms at p95. These measurements do not
demonstrate sustained 20 Hz physical camera control.

A separate matched case 002 injected five blank frames at steps 80–84
(4.00–4.20 simulated seconds). All five actions were zero; the first subsequent
frame restored tracking. The robot arrived at 13.10 seconds, versus 12.95 without
dropout, with 3.03 cm final error, 0.00676 m/s speed, 0.545 seconds dwell and no
collision. This check is separate from the 12-case denominator.

## Next experiment after this development fix

1. Freeze the M7.3 configuration and reserve new whole-room/camera seeds before
   further tuning. Keep an all-requested-goals denominator, including goals that
   are visually occluded. Report a second diagnostic breakdown for visible versus
   occluded endpoints; do not remove hard cases from the main success rate.
2. Improve single-view boundary estimation with native-resolution training labels
   and losses measured after floor projection. Evaluate on separate validation
   scenes, including different floor textures, robot colors, lighting, obstacle
   heights and camera poses. Case 007 is a perception/conservatism target, not
   evidence that hidden floor should be labeled free.
3. Address coverage explicitly. In simulation compare the current perched view
   with a better-coverage calibrated placement and, separately, a second view.
   Fuse only observed ground evidence with conservative conflict handling;
   report which additional view exposes a previously occluded goal. An alternate
   camera setup is a separate experiment, not a silent change to this benchmark.
4. Test persistent observation loss, glare/blur, calibration errors and moving
   occluders. Add map freshness and scene-change handling before claiming support
   for moving obstacles. Validate uncertainty coverage instead of treating the
   current covariance heuristic as a calibrated risk model.
5. Run the frozen system on at least 200 newly sampled room/goal episodes after
   implementation, retaining the original arrival/contact gates. Separate
   navigation, visibility rejection and perception failures. Only then assess
   whether reliability approaches the oracle controller. Physical camera/BLE
   commissioning remains a separate uncompleted gate.

The SAM/TAP temporal-student research program remains unimplemented. These
engineering fixes support that future comparison; they do not establish novelty
or superiority to published camera-navigation methods.
