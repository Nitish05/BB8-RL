## Scope and ownership

Implement and evaluate both remaining immediate capabilities: navigation beyond
the old development room and a small live RGB-grounded interaction/learning loop.
No personality, physical real-time operation or generic object understanding
claim follows automatically. Existing parameters, policy and vision weights are
frozen for the held-out evaluation; all 48 requests remain in its denominator.

Parallel agents own (1) new held-out provisioning and evaluation code/tests,

The integration owner controls shared runtime/world/purpose changes, docs and
all native execution. Only one native simulation may run at a time.

## Execution and acceptance gates

1. **Provision new navigation evidence.** Match each frozen layout, camera and
   appearance family in `navigation-heldout-v1.json`. Capture new RGB scans and
   estimate registration; never substitute the old map or simulator transforms.
   Build separately checksummed contained asset graphs with unchanged weights.
   Validate source provenance, scene match, unknown-cell blocking and rejection
   of incorrect family/map/registration identities before any policy run.
2. **Execute the frozen evaluation.** Serialize all 48 requests across both
   variants and camera modes 1/2/3. Independently score contacts, arrivals,
   localization losses, initial rejections, later probes and interventions with
   exact requested/executed denominators. Retain failures; do not tune on them.
3. **Verify native visual response rendering.** Freeze a small synthetic marker
   and resource-indicator contract, then capture action-dependent states from a
   real native camera, including missing/occluded/duplicate observations and two
   poses. A post-render overlay or numerical receipt does not satisfy this gate.
   Dedicated debug-scene RGB is acceptable only with explicit nonphysical scope,
   tested occlusion and no changes to normal navigation/validity camera evidence.
4. **Connect visual outcomes to persistent learning.** Derive entity identity,
   anchors and resource intervals from RGB. Admit before/after outcomes only for
   a matching authorized interaction, fresh evidence and stable association.
   Retain exact image hashes and immutable evidence. Missing, ambiguous, stale,
   stopped or duplicate/conflicting observations cannot create a new outcome.
   Reset restores resource episodes and knowledge separately; authority remains
   disabled after restart. Keep world-side effects and scorer truth outside the
   learner boundary.
5. **Compare histories and controls.** Freeze opposite histories, memory ablation,
   random/nearest/fixed choices, effect reversal and useless-object cases. Report
   learned choices and appropriate idle separately from route/effect failures.
   Native end-to-end runs must show actual choice, navigation, authorized action,
   changed RGB, learned memory and restart behavior. Explicitly distinguish any
   recorded-native replay benchmark from newly executed live interactions.
6. **Integrate and deliver.** Run targeted and complete non-native regression,
   independent validators, Ruff/frontend checks, relevant native cases and actual
   app validation if app behavior changes. Preserve exact sources/configuration,
   failure attempts and evidence indexes; update the completion ledger and
   limitations. Do not publish or replace existing assets/environments implicitly.

## Pixel-coordinate correction phase

The separate four-view acquisition first reproduced a 20 m renderer clip at a
21.63 m room depth. Explicit 25 m clipping restored the complete room without
changing poses or evidence bounds. The repaired capture still yielded no useful
map. Exact stage replay attributed its failure to the all-pixel photometric
patch gate, with nearly 99% of failed wide-view comparisons near checker edges.

Genesis exports viewport-centred K but reconstructs array rays with u+0.5 and
v+0.5. A fixed principal-point conversion of -0.5, derived from that convention
and the RGB readback, restored thousands of positive floor pixels under the
unchanged gates. This is diagnostic evidence, not a route result.

The completed repair phase adds explicit `pixel_coordinates` metadata and an opt-in
native export conversion, preserving legacy defaults and installed assets. New
derived metadata, RGB-only registration, all positive masks and map evidence
were rebuilt together. Old positive masks/FREE cells are not automatically
re-certified. The builder and runtime validate the convention, including
integer-centre resizing. The same whole-volume safety and original-goal utility
checks gate the proposed six-request development navigation run. Safety and evidence passed; utility failed, so all six remain unexecuted. Full regression and a separate legacy visual-learning smoke passed. All 373 legacy native camera-image sets, measurements and actions remain identical across the compatibility change. See the
retained `work/continuation-20260926-visual-heldout/PIXEL-CENTER-REPAIR-PLAN.md`
for ownership and acceptance details.
