# M7.8 — Scan memory and bounded camera occlusion control

This experiment implements the [M7.8 plan](M7_8_PLAN.md) in the separate BB8-RL
project. The environment is the original static, seven-box synthetic room. The
twenty scan RGB views are processed offline; only one fixed camera supplies RGB
during control. Reserved cameras 14, 17, 20 and 23 never contribute map inputs.

**Native occluded driving and visible arrival now pass on one supplemental
development route using fixed camera 20.** The original six cases remain blocked
by the estimated map: **0/6**, retained separately. This establishes a bounded
demonstration, not reliable navigation throughout the room.

## What changed

`mapping/scan_free_space.py` produces explicit body-height clear-space evidence.
Missing reconstruction points do not imply clear space. The producer intersects
the frozen learned traversability mask with the synthetic floor palette and, in
the geometry-filtered variants, floor-plane RGB correspondence. Entire projected
3D prisms must have support in separated scan views. Unknown and occupied cells
block exact continuous footprint, reaction and braking capsule checks.

The initial five-centimeter grid overestimated some conflicts and lost clearance
by testing the rectangle around a projected prism. V6 uses two-centimeter cells
and exact convex projection/pixel-square intersection. It retains the five-
centimeter assumed uncertainty margin. Its separate occupied layer contains
26,205 of 27,710 collision-height photometric points with support from at least
three distinct reconstructed views within five centimeters. Rejected estimates
remain in the immutable source cloud; rejecting them never creates free evidence.
The full original occupied memory and every intermediate map are retained.

`occluded_control.py` uses a command-conditioned first-order velocity model and
separate position/velocity error radii. It propagates missing observations, rejects
inconsistent reacquisition, remembers a certified route and asks the existing
actuator for zero when evidence expires. The frozen SAC policy supplies headings.
The guard scales speed only when the entire stopping envelope remains clear.
Pending commands remain in the reachable-speed bound for their full 150 ms
lifetime; an acknowledgement with an equal value does not erase their history.
V3 additionally accepts a complete command-only timeline sampled immediately after
the existing actuator advances and before each physics tick. Only completed
intervals reach the next prediction. Exact acknowledged transition times remove
historical timing uncertainty; all process-error and future-braking bounds remain.
The scalar acknowledgement interface retains its conservative fallback behavior.
V4 keeps a persistent target-centered reachable velocity ball instead of repeatedly
reconstructing it from a looser nominal-centered ball. Independent enclosure bounds
can tighten one another without changing the declared process-error magnitude.
The acceleration/deceleration cap switch is also included when it can affect the
reachable set.
V5 adds a stationary initialization phase: at least three current accepted visual
samples and velocity radius at most 0.05 m/s are required before first motion.
V6 starts visible arrival dwell only after the acknowledged target is zero and
all pending nonzero targets have expired; it preserves the original 0.5 s dwell.

Default limits are 0.15 m/s, one second without an accepted visual observation,
and an eight-centimeter position radius. The controller does not read simulator
position, velocity, obstacle geometry, collision flags, depth or renderer labels.
The actuator implementation and learned checkpoints are unchanged.

## Verification and limits

`run-scan-occlusion.py` freezes decisions before reading scoring truth. It records
native RGB, renderer head masks, acknowledged commands, controller diagnostics
and each 5 ms physics sample. Visibility is measured at 20 Hz: consecutive hidden
captures bracket a motion interval, but do not measure visibility at every physics
tick. Injected observation omissions are reported separately from real occlusion.
`audit-occluded-control.py` checks artifact hashes, source ancestry, static geometry,
timestamps, physical motion, uncertainty coverage and true arrival dwell.

Visible arrival is an estimated-state decision, independently checked against the
original true position/speed/dwell requirements (10 cm, 3 cm/s, 0.5 s). The current
controller tests estimated speed, not the entire velocity uncertainty ball; its
arrival signal is not a model-certified stopping guarantee. A false early arrival
therefore remains a failure in the independent score.

Metric scan poses, intrinsics, support plane, grounded opaque obstacles, no
overhangs, a static scene and the model's error/braking assumptions remain
conditions of this experiment. Camera registration uses an RGB-estimated pose;
the exact pose is used only to render and score the fixture. Simulation is
lockstep, with physics paused during image processing. It does not establish
real-time performance, uncalibrated handheld scanning or hardware readiness.

Artifacts live under `work/m78/`; failed variants and complete native logs remain
available there. Run native tests using the configured Genesis runtime and the
existing actuator; do not substitute geometry truth for a failed map.

The final non-GUI suite passes **364 tests**, with 20 opt-in Genesis/native GUI
tests deselected; Ruff passes. Actual native execution above is separate evidence.
Genesis Studio, the actuator implementation, the SAC checkpoint and the M7.5
vision checkpoint remain unchanged.

## Reproduce in this prepared workspace

Use a fresh output path so a failed run is never overwritten:

The archival scan runner expects the original native scan at
`work/scan/view-probe`, or an explicit `--scan-dir /path/to/view-probe`. These
capture inputs are not part of the interactive release bundle; the control room
uses portable map/calibration outputs instead.

```bash
BB8_PYTHON="$PWD/.venv-dreamer/bin/python" \
NUMBA_CACHE_DIR="$PWD/work/m78/numba-cache" \
PYTHONDONTWRITEBYTECODE=1 scripts/python.sh scripts/run-scan-occlusion.py \
  --protocol work/m78/supplemental-fixture/v6-camera20-r20-short/protocol.json \
  --memory work/m78/scan-free-memory-v6-hull-fine \
  --output work/m78/repeat-camera20 --max-steps 1200

BB8_PYTHON="$PWD/.venv-dreamer/bin/python" \
scripts/python.sh scripts/audit-occluded-control.py \
  --protocol work/m78/supplemental-fixture/v6-camera20-r20-short/protocol.json \
  --memory work/m78/scan-free-memory-v6-hull-fine \
  --episodes work/m78/repeat-camera20 --output work/m78/audit/repeat-camera20
```

The original protocol is `work/m78/audit/protocol.json`; supplemental moving
controls use `work/m78/supplemental-fixture/v6-camera20-controls/protocol.json`.
Map production commands, rejected variants and source ancestry are recorded in
`work/m78/scan-free-memory-notes.md`. Final accepted logs and independent reports
are `work/m78/native-v6-camera20-controller-v6` and
`work/m78/audit/native-v6-camera20-controller-v6`.
