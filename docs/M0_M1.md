# M0–M1: native runtime and synthetic BB-8 world

BB8-RL is an independent project that uses unmodified Genesis Studio 0.2.0
(tested at `cd20c8c`) for Project JSON, scene construction and native authoring.
All BB-8 control, task configuration, assets, tests and future training code live
here. Genesis World is the authoritative physics/rendering engine.

The [synthetic M2 room](M2_SYNTHETIC.md) now provides a larger arbitrary room,
random obstacles and a fixed elevated camera. Its dimensions and calibration are
synthetic by user choice; physical measurements do not block simulator work.

For setup and the repository boundary, see [README](../README.md). From BB8-RL:

```bash
./scripts/run-bb8.sh world validate
./scripts/run-bb8.sh fixture-check --backend cpu --output work/fixture.json
./scripts/run-bb8.sh simulate --viewer --drive 0.5 0 --seconds 4
./scripts/run-bb8.sh doctor --backend metal --device mps --output work/doctor
./scripts/open-studio.sh
```

`fixture-check` checks the M1 dynamics fixture. Since M3, `env-check` runs the
Gymnasium checker on the navigation task; see [M3](M3.md).
`simulate` brakes in the last second (half the duration for short runs), then
closes after 0.5–60 simulated seconds. Control-C cancels and closes resources.
`--render` enables a separate world-fixed observation camera. CPU is the default;
explicit Metal requests fail rather than fall back. The native viewer runs on
the main thread.

## World and response model

The world is a synthetic 3 m square floor with four solid walls. Body radius
0.037 m, effective total mass 0.2 kg, friction and every drive parameter are
**provisional synthetic values**, not measurements or manufacturer specifications.
The original schematic primitives are not a replica suitable for training real
special-edition appearance recognition. The independent non-colliding head sphere
stays upright and follows the shell's position. Its effective contribution is
approximated in the body's mass and inertia.

`PlanarDriveBackend` is an optional generic capability separate from joint control.
Commands carry X/Y, a monotonic simulation timestamp and an expiry. Components
are checked, then projected onto the unit disk. The backend models speed dead zone,
heading offset, latency, response time, bounded acceleration and braking. Stale,
future, replayed, nonfinite and overlong commands fail clearly. A zero request
preserves heading. Explicit `stop()` clears delayed commands immediately and
subsequent physics ticks apply bounded braking. It does not teleport velocity to zero.

Only `bb8_rl.control.genesis_backend` translates commands to Genesis
actuators. Its public six-DOF motion-axis check rejects incompatible bodies, and
real-engine tests establish X/Y world-frame behavior after the shell rolls.
Forces are bounded by effective mass and the configured acceleration limits.
Genesis integrates motion, sphere rotation and wall/floor contacts. No body pose
or velocity setter is used to drive the robot.

The fixture is intentionally **single-environment**. Public scene reset restores
initial positions/velocities; the runtime clears active and pending commands,
heading, clocks, contact counters, camera history and observation scheduling.
It is an episode-boundary reset, not a full deterministic solver checkpoint.
M3 adds scalar episode resets of obstacles, planner state and reward/goal state.
Indexed batched resets and trainer resume remain later work. World validation checks the body, head, physical square boundary,
fixed camera and command timing before initializing Genesis.

Contacts are sampled every 5 ms physics step and floor contact is excluded from
the wall/object counter. Ten physics steps form a 20 Hz action loop. The RGB
camera is scheduled independently at 30 simulated FPS, retaining at most four
timestamped frames. Sequential rasterizer output is used; no CUDA batch rendering
or Mac parallel-render throughput is claimed.

## Diagnostics and remaining gates

The doctor runs bounded isolated CPU, requested-backend and learner probes. It
writes a machine report, individual probe results, RGB PNGs, logs and an exact
package-version snapshot. Reports distinguish this project's source hash/revision
from the Studio dependency's revision and working-tree status.

Each probe has a 180-second timeout. Timings exclude initialization and include
20 actions with state reads, actuation, contacts, head updates and scheduled RGB
rendering. They are fixture smoke benchmarks, not training throughput. Memory is
peak process RSS. MPS testing performs finite float32 forward/backward and Adam
updates; no RL model is trained by this check.

The checked-in `configs/navigation/requirements-macos-py312.lock.txt` records the
tested native package versions. It is not a hashed wheel archive or cross-platform
resolver lock. Native dependencies can be shared with the existing Studio runtime
through the launcher, or installed into this project's own `.venv` as documented
in the README. Neither route requires changes inside Studio's source tree.

An external camera check is explicit:

```bash
./scripts/run-bb8.sh doctor --backend cpu --device mps --camera-index 0 --output work/camera-doctor
```

It captures 60 frames and reports delivered FPS, dimensions, host monotonic arrival
timestamps and p95 read duration. Read duration is not calibrated exposure-to-host
latency. No physical camera images are saved. Camera calibration, availability and
BLE compatibility remain pending. Simulation never imports or instantiates a BLE
adapter, and a passed simulation gate does not complete the hardware gate.

The original M0–M1 fixture is now used by the M3 Gymnasium task and
[M4 SAC + HER trainer](M4.md), which supports episode-boundary resume. There is no
perception model, click-to-go UI or physical driver in those stages. Batched environments and
physical transfer remain later work in this repository.

[M5](M5.md) adds a DreamerV3 adapter and a corrected-reward comparison with SAC.
Both use oracle state/map observations and native Genesis physics. Dreamer's
optional CPU dependencies live in a BB8-RL overlay, with the authors' pinned code
under ignored work storage. This adds no perception or hardware capability.

[M6](M6.md) adds full-map waypoints and learned low-level SAC/Dreamer controllers,
trained from successful demonstrations and RL with auxiliary teacher supervision.
The learned policies supply all evaluated drive commands through the existing
force-based adapter. The original 10 cm / 3 cm/s / 0.5 s arrival gate is retained;
arrival now terminates this wrapper's training episodes. M6 evaluates oracle
state/map navigation with a 60-second episode limit, not camera perception.

[M7.1](M7.md) starts camera control using native rendered RGB, synthetic pinhole
calibration, color-based localization/free-floor classification and a temporal
position/velocity filter. The camera controller receives no simulator pose, map,
depth or segmentation IDs; a separate harness reads truth only for scoring.
Missing/stale/ambiguous observations request bounded braking. The initial baseline
reached 1/12 development goals and aborted the other 11; it does not inherit M6's
reliability. The research choice and implementation stages are in [M7 research](M7_RESEARCH.md).

[M7.2](M7_2.md) adds two small supervised RGB networks and a renderer-labeled
dataset split by whole room/camera setup. A corrected visible-floor/self target
and self-pixel loss weighting improved the camera development pilot to 6/12
arrivals, zero collisions and six map/route aborts. The head network still uses
neutral-color crop proposals, and temporal filtering/covariance remain analytic.
Five missing frames produced zero drive commands followed by reacquisition and
arrival. Measured calibration, hardware, SAM/TAP inference, recurrent perception,
calibrated uncertainty and fresh camera acceptance tests remain pending.

[M7.3](M7_3.md) adds RGB-guided boundary refinement and continuous visible-space
checks around a finer camera map. Certified endpoint connectors and adaptive
segment sampling address conservative grid rejection; waypoint advancement now
checks the next segment. The repeated development suite reaches 8/12 goals with
zero collisions, with four visibility/perception aborts. Renderer masks remain
scoring-only, the learned checkpoints remain frozen and no actuator or Studio
changes are introduced. Occlusion, calibration transfer and fresh camera-room
acceptance remain incomplete.

[M7.5](M7_5.md) adds up to three fixed native camera objects, timestamped RGB-only
observation fusion and whole-room multi-view training splits. Independent held-out
perception audits retain missing/ambiguous detections in their reporting. A metric
3D memory contract retains observed free/occupied evidence, leaves unknown space
blocked and invalidates changed scene/camera registration. This is an observation
and memory substrate; no scan reconstruction or occluded-driving capability is
claimed. Existing SAC, single-camera control and actuation boundaries are unchanged.

[M7.6](M7_6.md) now runs actual RGB reconstruction in an isolated MapAnything runtime
and imports estimated occupied surface voxels without certifying free space. Known
metric scan-camera poses establish scale; this is not uncalibrated handheld SLAM.
The fast position-only observer has exact recorded detection parity, including real
box occlusion, and the deadline wrapper discards late results without committing
tracking history. Native timing covers two cameras in a stationary scene. Separate
causal prediction replays quantify occlusion drift while preserving measured versus
predicted state. Map accuracy, registration and braking-path checks remain required
before those modules can drive through occlusion.

[M7.7](M7_7.md) adds learned RGB correspondence registration, calibration of learned
depth against triangulated RGB anchors, and multiview photometric refinement.
Four reserved camera views pass independent registration with at most 8.7 mm
position error. Dense map p95 error falls from 16.55 to 9.89 cm without dropping
accepted samples; a separate, more precise photometric layer has lower coverage.
Known synthetic scan poses still establish metric scale. New surface memories
contain estimated occupied evidence only; missing surfaces remain unknown and
neither layer enables driving through occlusion. Optional matching dependencies
and pretrained weights remain in an isolated experiment runtime.

[M7.8](M7_8.md) adds scan-derived clear volumes, exact capsule checks and a
command-conditioned controller with explicit missing-observation limits. A
separate scorer checks native renderer visibility, every physics tick, command
acknowledgement timing and the original true arrival gate. Rejected maps and
blocked original routes remain in the report; supplemental tests selected after
map inspection are separate development evidence. One supplemental native route
now demonstrates 6.7 cm of motion between fully hidden captures, reacquisition
and verified visible arrival. Three moving dropout/invalid-memory controls pass;
the original six routes remain blocked. No Studio, actuator or policy
checkpoint changes are required, and no hardware is connected.

## Verification

The optional [persistent exploration experiment](AGENCY_PLAN.md) adds a place
choice learner above this same native stack. It selects only currently certified
estimated-map anchors and submits them to the existing controller; it does not
change actuators, physics, camera observations or map clearances. SQLite retains
actual navigation outcomes under a stable robot identity and a hash of all
checked map files. Exploration always starts disabled. Stop/Pause, a manual goal,
reset, camera changes, heartbeat expiry and lost localization revoke it; visual
recovery cannot resume an intention. Optional-memory errors leave manual
navigation available. A separate local semantic model trial has no motor access.

The [synthetic comparison](AGENCY_EXPERIMENT.md) measures acquisition, restart
retention and preference reversal for fixed, memory-only and learned-value
selectors. It is a bandit experiment with designed consequences, not evidence
of a social personality or recurrent RL. Native runs and independent motion
checks are recorded in [the integration report](AGENCY_NATIVE_RESULTS.md).

[M7.9](M7_9_PLAN.md) adds a loopback browser control room and a separate native
worker for one-to-three-camera navigation. Map clicks or metric coordinates feed
the existing route, uncertainty and stopping checks. Stop, Reset, command
generations and heartbeat expiry cancel stale motion. Demo models/map/calibrations
are explicitly installed from a checksum-verified release. The
[user guide](GETTING_STARTED.md) documents launch and camera modes;
[validation](M7_9_VALIDATION.md) records native outcomes. Studio remains unchanged.

Interactive route planning now uses the robot radius, clearance margin and
current RGB position uncertainty together. This fixes a fixed-10-cm search that
could repeatedly propose a route rejected by the independent, larger clearance
check. Losing clearance stops motion; while localization remains usable, a later
visible observation can establish a new route. Map evidence and stopping/arrival
gates are unchanged.
Arrival also waits through the existing model's braking-tail interval before
starting the full visible dwell; the [route-fix report](M7_10_ROUTE_FIX.md)
records the initially premature arrival and subsequent regression evidence.

[M7.11](M7_11_RESULTS.md) compares seven configurations in 14 tuning runs and
checks the selected profile against seven separately fixed validation cases.
The interactive default is `reserve-3cm`: 3 cm fixed margin, 15 cm/s speed cap
and 4 cm additional route-search clearance to avoid braking deadlocks at corners.
Camera uncertainty, braking bounds and visible arrival checks remain unchanged.
The reserve can reject tighter destinations; this is a one-room comparison.
The M7.12 route search prefers wider cached grids, then retries the exact required
radius if quantization disconnects the route. Every returned segment retains the
complete clearance requirement, including the 4 cm reserve.
Use `--control-profile baseline` to reproduce the prior interactive settings.

[M7.12](M7_12_SCAN_COVERAGE.md) extends the prepared scan from 20 to 48
RGB views using one moving camera, then reuses the map with the same fixed live
cameras. New free cells require four separated views and a two-pixel projection
guard; accepted earlier evidence and occupied conflicts are retained. Whole-map
geometry and input-provenance checks are independent of native arrival scoring.
Supporting-view storage now preserves up to 64 views, with exact compatibility
for existing 20/32-view maps. The SAC/vision weights and actuator are unchanged.

[M7.13](M7_13_RESULTS.md) makes localization validity explicit: uninitialized,
measured, predicted, lost and reacquiring. Short command-conditioned predictions
remain usable only within the existing one-second occlusion and 8 cm position
radius limits, with valid timing and the unchanged control checks. Expiry clears
the goal and route, removes the usable current pose/bound, and displays a labeled
last-seen ghost with simulation age. Multiple fresh, consistent visual frames
and a new motion-initialization check are required for recovery. Reacquisition
is bounded to 12 cm from the last valid prediction frozen at loss. This reference
includes valid motion after the last visual fix and does not move with the
expired predictor. The last-seen ghost remains the historical visual fix, not
the recovery reference. This is bounded local recovery, not global
relocalization; a robot outside the gate requires reset. Recovery leaves the
robot stopped until the user submits a new destination.

The raw conservative prediction bound stays in diagnostics and is never clamped
by the UI. A separate braking-region diagnostic is finite only under its declared
stopping assumptions and has no motion or arrival authority. A zero command is
not a zero-velocity observation. The [plan](M7_13_PLAN.md) and
[research review](M7_13_RESEARCH.md) explain this separation. Existing model/map
assets, actuator, Genesis Studio dependency, speed limits and arrival gates are
unchanged; native validation is recorded in the results report.
