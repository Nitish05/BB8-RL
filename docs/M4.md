# SAC + HER training and episode-boundary resume

The [execution plan](M4_PLAN.md) defines the first three-seed experiment. The
implementation stays in BB8-RL and uses Stable Baselines3 2.9.0 with the existing
Gymnasium task. No Studio changes, BLE commands or image perception are involved.

The original pilot exposed an early-failure reward incentive. Its original config
is retained for reproducibility. `configs/training/sac-her-penalty-v2.yaml` uses
failure penalties of 100 instead of 10 in a separate task, removing that incentive
at gamma 0.98 with zero control cost. Its 6,000-step diagnostic screen still failed
all four validation cases; the penalty correction alone has not produced useful
navigation. See the plan amendment and measured report before extending training.

## Commands

From BB8-RL, using the selected native runtime:

```bash
./scripts/python.sh -m pip install 'stable-baselines3==2.9.0'
./scripts/run-bb8.sh train --config configs/training/sac-her.yaml --output work/my-training
./scripts/python.sh scripts/run-sac-pilot.py --output work/my-three-seed-pilot
```

For the separate corrected-reward screen:

```bash
./scripts/run-bb8.sh train --config configs/training/sac-her-penalty-v2.yaml --output work/my-corrected-training
```

Evaluate its checkpoints with `--task projects/bb8/synthetic-room/task-penalty-v2.yaml`;
the evaluator rejects substituting the original task because its reward contract differs.

The first command installs the optional learner dependency. The second trains
one configured seed. The third executes the declared 17/29/43 pilot, restarts seed
17 at its midpoint, evaluates initial/mid/final policies, and runs paired A*/random
references. It takes a fresh output directory and retains every stage log.

Inspect a run's `latest.json` for its complete checkpoint directory. To continue,
copy the training YAML, increase `total_steps` (an absolute target), then use:

```bash
./scripts/run-bb8.sh train --config work/continued-training.yaml --resume work/my-training/checkpoints/step-000006000 --output work/my-resumed-training
./scripts/run-bb8.sh evaluate --task projects/bb8/synthetic-room/task.yaml --suite validation --episodes 12 --controllers sac-her --checkpoint work/my-resumed-training/checkpoints/step-000012000 --output work/my-policy-evaluation
```

Checkpoint step counts above are examples: use the paths actually recorded in
`latest.json`. Episode-boundary completion usually overshoots nominal targets.
When copying a config, keep its `task` path resolvable relative to its new location
(an absolute path is allowed). Resume refuses changed source, task/world/reward
contracts or optimizer settings. Only total target, checkpoint interval and the
task path's location may change; the resolved task contract must remain identical.
Restore the recorded dependency versions when moving a run to another environment.

## Learning contract

- SAC uses 128/128 hidden units, batch 128, a 20,000-transition replay buffer,
  constant learning rate 0.0003, gamma 0.98, tau 0.005 and automatic entropy tuning.
- HER samples future achieved goals, including speed, with four virtual goals per
  real goal. Copied info dictionaries preserve collision/control penalties. True
  failures stop bootstrap; time-limit truncations preserve bootstrap.
- The raw observation/reward/action contract is unchanged. The feature extractor
  scales position by room half-extent and velocity by configured maximum speed,
  averages each local-map channel into 7×7 bins, and calculates desired-minus-
  achieved goal coordinates inside the policy after relabeling. There are no
  running normalization statistics or unrecorded observation wrappers.
- Optimization begins after 1,500 transitions. The buffer must exceed two full
  episode horizons and warmup must cover one. HER never samples an unfinished
  first episode. One update is performed per transition in each optimized rollout.
- The trainer calls the public learning API for one complete episode at a time.
  All schedules are constant; SB3's per-call progress fraction is not used for
  a learning-rate or exploration schedule. Reported throughput uses the trainer's
  own overall clock, not a per-call FPS counter.
- Success does not terminate training; the evaluator stops at 0.5 s arrival dwell.
  Training logs distinguish any arrival during an episode from success at its end.

The policy receives local oracle observations, not images or the full map. A*
receives the full oracle map and uses a planned route. Its performance is a useful
reference but not an equal-information learned-controller comparison. Authored
room validation varies starts/goals in one room; it does not establish room-layout
generalization or physical transfer.

## Checkpoints and cancellation

Each checkpoint contains:

| File | Contents |
| --- | --- |
| `model.zip` | SAC networks, optimizers, entropy state and counters |
| `policy.pt` | Inference policy and fixed feature scaling |
| `replay.pkl.gz` | Complete HER replay with info/timeout metadata |
| `rng.pkl` | Python, NumPy, Torch, optional MPS and action RNG states |
| `state.json` | Contract, source hash, next episode, settings, counters and file checksums |

Files are written to a staging directory and the complete directory is renamed
atomically before `latest.json` changes. Checkpoints require a fresh next episode
and no unfinished HER trajectory. Environment seeds derive from the training seed
and episode index; the next episode is reconstructed before policy RNG is restored.
Genesis internal solver state is not serialized. Resume is explicitly at an
episode boundary, without a promise of bit-identical cross-device/GPU replay.

The first SIGINT/SIGTERM request finishes the current episode and its gradient
updates, saves a complete checkpoint, records cancellation and exits with code
130. A second interrupt stops immediately and keeps the prior complete checkpoint.
Unexpected/numerical failures mark the run failed and preserve existing complete
checkpoints. Incomplete `.partial` directories are never loaded as completed runs.
Only load trusted locally generated checkpoints: model/replay files use pickle.

## Runtime selection and evidence

Both CPU and MPS passed a real 240-transition SAC/HER probe on the native Mac.
Each performed 220 gradient updates. Optimization took approximately 0.59 s on CPU
and 3.54 s on MPS for this small network/batch, excluding physics and startup.
CPU is therefore the pilot default, using two Torch threads; CPU physics is a
separate selection. Explicit unsupported MPS requests fail rather than fall back.

Runs contain machine/package/source/configuration manifests, per-episode JSONL,
SB3 CSV losses and checkpoints. Evaluation records checkpoint checksums, source
metadata, all episode outcomes/trajectories and timing. No claim of learning or
navigation quality should be made merely because training completed; read the
measured pilot results and retain failures alongside successes.

The default replay's dense observation arrays occupy roughly 220 MB before
compression. Checkpoints compress replay on disk; model and inference artifacts
are separate. Runs remain in ignored `work/` or `runs/`, not source control.
