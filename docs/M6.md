# Reliable learned waypoint control

M6 changes navigation to a full-map A* planner followed by a learned continuous
controller. SAC and DreamerV3 produce every drive command during evaluation.
The planner produces waypoints, never drive commands. Teacher actions are used
only in demonstration collection and training losses. This is a hybrid system
using oracle state and map data. It does not yet consume the perched camera.

The preregistered [M6 plan](M6_PLAN.md) sets a 95% arrival target on 200 held-out
synthetic cases for each frozen controller. M5's zero-success results motivated
the change, but M6 is not an equal-observation rerun of that experiment.

## What changed

The previous local observation could hide an obstacle detour, the reward rarely
exposed success, and the discount horizon was short relative to a room crossing.
M6 uses five inputs: X/Y displacement to the current waypoint in metres, X/Y
velocity divided by 0.35 m/s, and a final-waypoint flag. A* uses the existing
inflated occupancy map and connected start/goal sampler. Intermediate waypoints
advance within 4.5 cm and below 6 cm/s; these thresholds do not relax arrival.

Arrival still requires **within 10 cm of the final goal, below 3 cm/s, for 0.5 s**.
Arrival now terminates a training episode. Collision/boundary violations also
terminate; the 1,200-action limit truncates at 60 simulated seconds. Physics,
contact detection, action frequency, and the force-based actuation adapter are
unchanged. Every learned action passes through that adapter.

The reward is `10 * route_progress - 0.01 - 0.01 * squared_action_norm`, plus
0.2 when inside the distance/speed gate, 25 for arrival, and minus 50 for failure.
Progress measures remaining polyline route length before/after an action.
Discount is 0.995, corresponding to a nominal 200-action/10-second horizon.

64 successful expert episodes supplied 14,979 physical transitions in procedural
training rooms. The feedback teacher labels states only in training. Both
learners retain an auxiliary imitation loss with weight 100 during RL; the
teacher is not an observation supplied to either policy.

| Setting | SAC | DreamerV3 |
| --- | --- | --- |
| Actor | 128/128 MLP | Official size1m recurrent latent policy |
| Initial training | 4,000 actor imitation updates | 3,000 sequence updates from demonstrations |
| Additional teacher data | 100,000 synthetic recovery states | Labels on on-policy training states |
| Online physical actions | 20,000 | 10,000 |
| Online RL updates | 5,000 | 1,250 |
| Batch | 256 transitions | 4 sequences × 32 steps |
| Learning rate | 0.0003; initial imitation 0.001 | 0.0003, 100-step warmup |
| Evaluation action | Actor mean | Actor mean, seeded stochastic recurrent latent |

SAC retains twin critics, target updates and its entropy objective (coefficient
0.0001). The auxiliary gradient is added at the actor optimizer step. Dreamer
retains its recurrent world model, imagined actor/value training, reconstruction,
reward and continuation losses. Its local subclass adds actor supervision on
posterior replay features. The official upstream code is unchanged and pinned to
`e3f02248693a79dc8b0ebd62c93683888ddaccfe`. Replay context is zero; policy standard
deviation bounds are 0.01–0.1. Teacher labels are excluded from encoder inputs.

## Run and reproduce

From the separate BB8-RL repository, use the same overlay as M5:

```bash
bash scripts/setup-dreamer.sh
export BB8_PYTHON="$PWD/.venv-dreamer/bin/python"
./scripts/python.sh -c 'from bb8_rl.guided import collect_demonstrations; collect_demonstrations("work/my-m6/demonstrations")'
./scripts/python.sh scripts/run-guided.py sac --demonstrations work/my-m6/demonstrations/demonstrations.npz --output work/my-m6/sac
./scripts/python.sh scripts/run-guided.py dreamer --demonstrations work/my-m6/demonstrations/demonstrations.npz --output work/my-m6/dreamer
./scripts/python.sh scripts/run-guided.py evaluate --algorithm sac --checkpoint work/my-m6/sac/model.zip --count 50 --output work/my-m6/sac-validation
./scripts/python.sh scripts/run-guided.py evaluate --algorithm dreamer --checkpoint work/my-m6/dreamer/model.pkl --count 50 --output work/my-m6/dreamer-validation
```

Every output must be fresh. Each evaluation count is **per room family**. The
two families are the authored 4 m room with seven obstacles and procedural 3 m
rooms (empty, barrier, corridor, scatter). Authored evaluation changes starts and
goals, not the seven-obstacle map. Procedural evaluation changes layouts too.

Validation uses episode seeds `15000+i` and layout seeds `10000+i`; final test uses
`25000+i` and `20000+i`. Training uses disjoint seeds. The preliminary 24-case
validation is a subset of the later 100 cases, not 24 additional independent cases.
Final testing rejects candidates without a matching completed validation result
of at least 95/100 arrivals. Test candidates are frozen by SHA-256:

```bash
./scripts/python.sh scripts/run-guided.py evaluate --algorithm sac --checkpoint work/my-m6/sac/model.zip --count 100 --split test --validation work/my-m6/sac-validation --output work/my-m6/sac-test
./scripts/python.sh scripts/run-guided.py evaluate --algorithm dreamer --checkpoint work/my-m6/dreamer/model.pkl --count 100 --split test --validation work/my-m6/dreamer-validation --output work/my-m6/dreamer-test
./scripts/python.sh scripts/check-guided-checkpoints.py --sac work/my-m6/sac/model.zip --dreamer work/my-m6/dreamer/model.pkl --output work/my-m6/checkpoint-check.json
```

The recorded M6 final test has already been designated; do not tune against its
results and then call it an unseen test again. Register new test seeds before
selecting any future candidate. CLI enforcement checks validation/hash, but does
not prevent a human from reusing seeds in a different output directory.

Evaluate `bc-only.zip` with `--algorithm bc` for the pre-RL SAC actor ablation.
Evaluate Dreamer's `offline.pkl` with `--algorithm dreamer` for its pre-online
checkpoint. The latter has already undergone Dreamer world-model and imagined
RL updates, so it is not a pure behavior-cloning baseline.

For a relocated checkout, set `BB8_DREAMER_ROOT` to the same pinned upstream
checkout. Keep Dreamer's JSON sidecar beside its pickle. Loading checks its hash
and feature version. Model artifacts are trusted local Python checkpoints, not
an interchange format for untrusted files. Exact M6 training resume is not
implemented. Use fresh output directories for retraining.

## Evidence and limits

Raw runs are under `work/m6`: source/machine/configuration manifests, training
metrics, checkpoint hashes, every evaluation trajectory, and summaries. The
reload check verifies exact saved parameter restoration and repeated seeded
inference, with teacher functions replaced by functions that raise if called.
The tests retain the original dwell/speed gate and distinguish time limits from
terminal outcomes. Genesis Studio source is unchanged.

The behavior-cloning baseline is essential: a successful hybrid RL controller
does not establish that reinforcement learning improved on imitation. Online
teacher regularization also prevents attributing gains solely to the RL losses.
Training uses one seed per algorithm, fixed synthetic dynamics and a fixed drive
calibration. Timing runs overlap, so wall times do not rank training efficiency.
Success applies to reachable goals sampled by the task, static obstacles, oracle
localization and map access. It is not evidence for arbitrary rooms, moving
objects, camera occlusion, real BB-8 dynamics, or physical deployment.

Legacy machine manifests can list a shadowed dependency distribution; the
delivered `runtime-proof.json` records the versions actually selected by Python.

## Recorded result

Both frozen final checkpoints reached **200/200 test goals**, with no contacts,
boundary failures or timeouts: 100/100 in each room family. The 95% Wilson interval
for each aggregate success rate is 98.12%–100%. SAC's mean final error was 2.97 cm
and arrival time 13.18 s; Dreamer's were 2.53 cm and 12.68 s. The original arrival
distance, speed and dwell gates were verified for every successful test case.

Each passed 100/100 validation before final testing. The SAC behavior-cloning-only
actor also passed 100/100 validation; these results establish no success-rate
benefit from SAC fine-tuning over imitation. Dreamer improved from 1/24 before
online training (23 contacts) to 24/24 on the same development subset after online
RL plus teacher supervision; the separate contributions were not isolated.

46 non-GUI tests and eight native Genesis/task tests passed. The checkpoint check
restored 261 Dreamer parameter/optimizer tensors and repeated eight-action seeded
inference traces exactly within this runtime, with teacher functions disabled.
SAC's loaded policy also reproduced its trace. Static/dependency checks passed.
