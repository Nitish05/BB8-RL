# Persistent memory and personality for BB8

Research date: **24 September 2026**. Scope: an externally observed, nonverbal mobile companion using the existing SAC navigation system. This is a research comparison and proposed design; no models were installed or benchmarked. The available machine is an Apple M5 Pro with 48 GB unified memory, as observed by the parent task. Papers dated March–August 2026 below precede this review date. The 2023 systems are included as architectural foundations, not presented as recent releases. PEPA and current foundation-model selection are covered separately by the parent task.

The best first implementation is a small persistent agent above the existing navigator: typed memories with provenance and expiry, an explicit intention queue, and a restricted behavior catalog. A language model can interpret experiences and propose intentions. It should not supply localization, collision clearance, or motor commands. None of the reviewed results establishes a robot that independently develops a humanlike personality through ordinary companionship.

## What actually changes with experience

Four mechanisms should be measured separately:

| Mechanism | Persistent change | What it demonstrates |
|---|---|---|
| Prompted persona | A configured character description | Designed behavioral tendencies |
| Episodic or semantic memory | Stored events, summaries, facts and preferences | Experience-conditioned behavior without changing model weights |
| Skill or prompt adaptation | Saved programs, rules or revised prompts | Nonparametric improvement of the agent system |
| Learned preference policy | Updated numerical parameters or model weights | Statistical learning, if evaluated on withheld interactions |

Remembering that a user rejected an approach is useful adaptation. It does not by itself establish a learned policy. Likewise, an LLM writing “I enjoy exploring” into memory is a generated character statement. A defensible claim would identify the changed parameters, feedback signal, persistence boundary, and improvement on new situations.

## Comparison and reading record

**Generative Agents, 2023.** Read architecture §§4.1–4.3, controlled evaluation §6, and the two-day deployment §7. The system retrieves memories by relevance, recency and importance, generates reflections, and revises plans. Twenty-five Smallville agents exhibited coordinated behavior. One hundred human raters assessed interview believability; full architecture TrueSkill was 29.89 versus 21.21 without memory, planning and reflection. This measures perceived consistency in that setup, not human equivalence. The authors also report embellished memories. Model weights are unchanged; persona, memory and planning condition generation. For BB8, the useful transfer is continuity of routines and unfinished intentions, with explicit evidence behind reflections. The [paper](https://arxiv.org/html/2304.03442v2) and [official Apache-2.0 repository](https://github.com/joonspk-research/generative_agents) were inspected; its Python/Django simulation and historical API integration are not a robot runtime.

**Voyager, 2023.** Read method §2, results §3.3, and skill-library transfer experiments. GPT-4 proposes a curriculum and executable skills, improves them using execution feedback, then stores successful programs. It gathered 63 unique Minecraft items over 160 prompt iterations, reported as 3.3 times its comparator; diamond-tool completion occurred in only one of three runs. Its learning is persistent executable-program acquisition without GPT-4 fine-tuning. Structured game state supplies information unavailable to an RGB-only robot. BB8 could borrow reusable, tested behavior macros, but generated code should not gain direct actuator access. The [paper](https://arxiv.org/html/2305.16291v2) and [official MIT repository](https://github.com/MineDojo/Voyager) were read. The documented Python/Node/Mineflayer stack supports Minecraft, including macOS, rather than Genesis navigation.

**Concordia, 2023 foundation with continuing development.** Read the agent/component and Game Master methods, grounded-variable examples, and implementation discussion. Identity, observations, plans and associative memory condition an LLM; a Game Master resolves intended actions into outcomes. The original report provides illustrative simulations rather than a quantitative demonstration of learned preferences or robot reliability. Its authors explicitly discuss uncertainty about simulation-to-human generalization. Concordia is useful for testing a companion against scripted social situations, while Genesis and deterministic checks should decide physical outcomes. The [report](https://arxiv.org/html/2312.03664) and [official Apache-2.0 repository](https://github.com/google-deepmind/concordia) were inspected. This is an available modular simulation framework requiring an LLM interface, not a pretrained companion personality.

**MemGPT and current Letta.** Read MemGPT’s memory tiers, event-driven control flow and function chaining, and its nested-key retrieval experiments. The system pages external memory into limited context and edits working memory. These operations do not train the base model. Its nested-key experiment demonstrates benefits from iterative retrieval, but dependence on reliable tool calling limits transfer to small models. [MemGPT paper](https://arxiv.org/html/2310.08560v2). Current [Letta](https://github.com/letta-ai/letta) points to [Letta Code](https://github.com/letta-ai/letta-code), with the historical V1 server archived. The current Apache-2.0 harness documents persistent identity, editable memory, skills and scheduled execution. I inspected its [memory prompt](https://github.com/letta-ai/letta-code/blob/main/src/agent/prompts/letta_local_memfs.md), which makes the context-editing mechanism explicit. This is a credible persistence starting point, but its broad coding and self-modification affordances exceed BB8’s required behavior interface.

**Mem0, 2025 paper versus 2026 implementation.** Read extraction/update methods, LoCoMo setup and latency analysis. The paper uses extracted facts, retrieval, and ADD/UPDATE/DELETE decisions; its reported 26% relative judge improvement is against a particular OpenAI memory configuration. Full-context processing still achieved approximately 73% judge accuracy, with greater latency. This is conversational-memory evidence, not personality learning. [Paper](https://arxiv.org/html/2504.19413v1). The current [Apache-2.0 repository README](https://github.com/mem0ai/mem0) explicitly describes an April 2026 replacement: ADD-only memories, entity linking, keyword/semantic retrieval and temporal ranking. It also says its new headline benchmark figures concern the managed platform with proprietary optimizations. Therefore neither old paper behavior nor current hosted scores should be attributed automatically to an installed OSS version. Pin the implementation and test temporal supersession.

**ReMEmbR, September 2024 preprint / ICRA 2025.** Read memory construction, text/time/position retrieval tools, and NaVQA experiments. VLM captions are stored with timestamps and poses; an LLM repeatedly searches them and can return a semantic goal for another navigation system. NaVQA contains 210 questions from seven campus sequences. GPT-4o’s reported position errors were 5.1, 27.5 and 46.25 metres across short/medium/long sequences; the 8B local comparison performed much worse. These campus-scale errors cannot be translated directly to BB8, but they show why semantic recall is not metric clearance. [Paper](https://arxiv.org/html/2409.13682v1). The [official implementation](https://github.com/NVIDIA-AI-IOT/remembr) documents VILA, Ollama and Milvus, plus Nova Carter examples. Its [NVIDIA license](https://github.com/NVIDIA-AI-IOT/remembr/blob/main/LICENSE.md) restricts use to noncommercial research/evaluation. It is not a ready, unrestricted Mac companion package.

**WorldLines / ObsMem, 17 June 2026.** Read construction §3, typed-memory methods §4, all experiments §5, and limitations §7. Observer-grounded ingestion distinguishes witnessed events from reports. Separate event, state, belief and commitment records retain changes and uncertainty; consolidated episodes augment evidence. On 310 QA samples, ObsMem obtained 0.713 judge score; its downstream planning score was 0.684 versus Mem0’s 0.526, but that planning set contains only 21 samples. Hidden-state ablations are particularly small. Its structured simulator traces do not include realistic perception and actuation failures. This is the strongest conceptual fit for BB8’s existing measured/predicted/lost distinction, without establishing real-robot robustness. [Full paper](https://arxiv.org/html/2606.18847v1). I did not verify a released author implementation or code license; treat it as a design reference, not an installable dependency.

**ABot-AgentOS, 10 July 2026.** Read hierarchy, memory/self-evolution, training description and embodied evaluation §5.1. The design combines planning, context, skills, verification and multimodal memory; retained “evo-assets” support nonparametric adaptation. Separately, it describes teacher distillation, SFT and RL for a small model, with private training data and undisclosed production results. On an initial UnrealZoo subset, ABot with Qwen3.6-Plus achieved 61.96% task success versus 49.97% for its ReAct comparator. Navigation uses the benchmark’s NavMesh execution, so this is not a physical BB8 safety result. [Paper](https://arxiv.org/html/2607.10350v1). The linked [project page](https://amap-cvlab.github.io/ABot-AgentOS) failed to load during review; no runnable official release or license was verified. Adopt hierarchical separation, not the claim of an already solved robot operating system.

**PERMA, 24 March 2026.** Read event reconstruction, temporal checkpoints and metrics §4, implementation settings and result tables §5. Its ten profiles produce 580 queries and 808 events, with preference formation, noise and unrelated intervening conversations. It tests zero-memory, immediately relevant and post-intervention checkpoints. In the clean setting, MemOS achieved 0.811 MCQ accuracy versus Mem0’s 0.686; these results use specified hosted/local configurations, not a universal ranking. Interactive completion and memory fidelity reveal different weaknesses from recall alone. This is an evaluation benchmark, not a preference-learning algorithm. [Paper](https://arxiv.org/html/2603.23231v1), [official repository](https://github.com/MINE-USTC/PERMA). Code and evaluation instructions are present; I did not verify a top-level license. BB8 should borrow the temporal/interference tests and measure actual behavior separately.

**PersonaMem-v2, December 2025.** Read preference-data construction and SFT/GRPO training/results §§4.2–4.3. This supplies an actual parametric-learning example: a Qwen3-4B model is trained for preference following, and another procedure trains memory updates. The reported GRPO model reaches 53.8% MCQ and 56.0% open-ended performance versus GPT-5 Chat’s 45.6% and 46.2% on that benchmark. The mostly simulated histories and evaluator design limit broader conclusions. It learns how to infer and use preferences across users; it does not demonstrate one owner teaching an embodied personality online. [Paper](https://arxiv.org/html/2512.06688v1), [official repository](https://github.com/bowen-upenn/PersonaMem-v2). Training scripts and dataset links are available, but documented training uses CUDA 12.6; I verified neither a ready trained-model download nor a top-level license. Mac training readiness is unproven.

**PersonaMem-v3, August 2026 update.** Read data foundation, proactive/silence tasks and results §§4.1–4.4. It derives synthetic user worlds from privacy-preserving aggregated engagement data. Strongest overall reported accuracy is 53.7%; memory can improve efficiency while worsening stale preference use or inappropriate personalization, depending on the model. Proactive tasks explicitly include staying silent without a reason to interrupt. These are valuable companion-evaluation ideas, not evidence that an agent has its own enduring motivations. [Paper](https://arxiv.org/html/2608.21381v1). The v2 repository references v3 while also retaining a “coming soon” notice; release completeness was not established. I would not make it a required runtime dependency.

## What the issue trackers add

The following are reports in official repositories, not failures reproduced on our machine:

- [Letta Code issue 2666](https://github.com/letta-ai/letta-code/issues/2666), opened 2 June 2026, reports old memory remaining on disk while a new agent receives a blank context. Test stable BB8 identity, restart and session recreation explicitly; file persistence alone is insufficient.
- [Mem0 issue 6515](https://github.com/mem0ai/mem0/issues/6515), opened 22 July 2026, reports concurrent additions racing against a stale deduplication snapshot. Use idempotent event IDs and serialized memory commits; test retries and concurrent camera events. An open issue is evidence of an integration risk, not proof that every current version fails.

Repository README, license and issue inspection is not equivalent to installing or executing the software. Only the cited Letta memory prompt was inspected as a specific implementation file in this review. No runtime performance claim is made from these inspections.

## Proposed BB8 architecture and bounded experiment

The following is my design recommendation, not a measured result from the papers.

Use a small SQLite event store initially. Each record should retain event ID, time, camera or user provenance, confidence, location validity, and raw evidence reference. Maintain distinct current facts, historical events, user preferences, character settings and intentions. Summaries must cite source events. A reported object location must not silently become a measured location. Expired localization stays unusable even if a memory says BB8 was nearby.

Keep two personality records: a stable, editable design profile describing observable tendencies, and a learned preference model describing what this user welcomes. The latter can initially be a compact Bayesian or logistic ranker over a few behavior choices, updated only from explicit accept/reject feedback. Persist its parameters and sample counts. Uncertain inferred preferences should remain reversible hypotheses. This makes the learning claim testable without training the SAC motor policy or fine-tuning a large model from a handful of interactions.

Run one language-model planner asynchronously, triggered by meaningful events and a modest periodic timer. A 4B–8B quantized model is a sensible first candidate class for measurement on the available machine; that is an engineering starting point, not a verified throughput guarantee. Compare with a stronger reference model on the same saved observations. Reserve memory and compute for Genesis, camera inference and navigation; cap context, tool rounds and decision time. Queue VLM descriptions only on significant scene changes. External cameras require explicit camera/robot coordinate grounding rather than adopting ego-camera prompts unchanged.

The planner should output a typed proposal: behavior ID, referenced entity or permitted goal, rationale evidence IDs, priority, expiry and cancellation conditions. A deterministic arbiter can choose between a user task, a previously accepted routine, waiting, or a low-priority interaction invitation. Existing localization, map and stopping checks remain authoritative. Stop cancels intentions; recovery does not silently revive them. Rejection is recorded as an outcome rather than prompting repeated goal submissions.

Begin with four or five behaviors executable by existing capabilities: travel to an allowed place, wait nearby at a configured distance, retreat to an allowed place, or perform a bounded motion invitation. Any head, sound or light expression requires a separately verified actuator interface. Nonverbal personality should appear through timing, approach distance, patience and behavior selection, rather than generated claims about emotions. The agent should not infer private characteristics from appearance or treat absence of rejection as positive feedback.

Freeze a first evaluation before implementation results: several simulated users with explicitly different approach/play/quiet preferences, a preference reversal, irrelevant intervening events, an unavailable camera, a blocked goal, Stop, restart, and duplicated event delivery. Compare fixed persona only, persona plus memory, and persona plus memory plus learned ranker. Use separate interaction histories for fitting and evaluation, and prevent future preference changes from entering earlier decisions.

Report held-out preference-choice accuracy, reversal recovery, unsupported memory claims, expired-fact use, unnecessary interruptions, duplicate intentions and persistence across restart. Evaluate persona recognizability and user liking separately with blinded behavior clips; one can rise while the other falls. Retain navigation’s physical success, contacts, fresh-visibility and arrival gates. A successful first result would be more appropriate, consistent behavior across sessions with unchanged motion protections—not evidence of consciousness or general autonomous companionship.
