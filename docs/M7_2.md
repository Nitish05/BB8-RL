# M7.2 — first learned camera observer

This stage replaces the palette floor classifier with a small supervised network
and adds a learned head mask inside native-resolution RGB crop proposals. It is
an incremental implementation of the [M7 research direction](M7_RESEARCH.md),
not the full temporal student or foundation-model teacher pipeline.

## Scope and experiment plan

1. Render 40 separate synthetic room sequences, 128 frames per sequence. Assign
   complete scenes 0–23 to training, 24–31 to validation and 32–39 to development
   before training. Do not split neighboring frames across these groups.
2. Vary 3–8 obstacles, camera position/look-at/FOV, ambient light and light
   intensity. Randomize obstacle colors in half the scenes. Use exact synthetic
   camera calibration and a gray BB-8. Floor texture, robot appearance and room
   size remain fixed in this first experiment.
3. Use Genesis segmentation IDs and pose only to create labels and score
   predictions. Generate head crop locations from RGB, plus random negative
   crops. An oracle route controller moves the robot during data collection;
   neither its actions nor its map are inputs to the perception model.
4. Train two separate small U-Nets: a 320×240 floor/non-floor classifier and a
   64×64 native-resolution head/background classifier. Apply brightness/channel
   changes and small noise to training images, and spatial shifts to head crops.
   Use 1,500 AdamW steps, seed 17, batch sizes 4 floor images and 16 head crops.
5. Every 100 steps, select a floor threshold and checkpoint using the eight
   validation scenes. Penalize false-free floor pixels heavily. The checkpoint
   initial score is `20*false_free + 1-floor_recall + head_miss + head_false_detection`.
   This is an engineering selection criterion, not calibrated risk probability.
6. Freeze the selected weights and compare both floor observers on identical
   native images from the validation and development scenes. Report scene-wise
   floor IoU, recall, false-free fraction, head patch confusion and position error.
7. Run the frozen observer through the existing RGB controller on the same 12
   M7.1 development cases, using the frozen M6 SAC driving policy. Count original
   10 cm / 3 cm/s / 0.5 s arrivals, collisions and guarded aborts. These previously
   inspected scenarios are development cases, not fresh acceptance trials.

## Runtime boundary

The learned observer receives RGB and capture time. Its calibration object
contains intrinsics, extrinsics, known room extent and nominal head height.
The controller also receives a goal pixel. There is no inference-time simulator
pose, obstacle map, depth or segmentation buffer. The corrected map network
predicts visible ground plus visible BB-8 self pixels as traversable. A rendered
obstacle occluding BB-8 remains an obstacle label. Treating visible self as
traversable is an explicit self-occupancy assumption, not a geometric guarantee
about the floor hidden behind it. No other occluded region is relabeled.
The existing Kalman filter
estimates velocity and rejects outliers; the existing camera map/planner and SAC
policy generate drive requests through the existing control backend.

Head proposals still depend on neutral RGB color, and self-body clearing uses
the existing local color mask. Two nearby detections within four pixels are
merged as duplicate crop observations; multiple separated detections stop
control. Covariance is the existing geometric heuristic, not a learned or
calibrated uncertainty estimate. Floor thresholding is also heuristic and can
produce false-free pixels. Hidden floor is not filled from simulator geometry.

No SAM 3.1 or TAPNext++ weights are used in this stage: the training teacher is
the synthetic renderer. Temporal neural tracking, three-way free/occupied/unknown
prediction, learned uncertainty, real-camera adaptation and foundation-model
distillation remain later work. The full research direction is not yet validated
as novel or superior to published methods.

## Reproduction

Run from BB8-RL with the existing optional learner/simulation runtime and OpenCV:

```bash
export BB8_PYTHON="$PWD/.venv-dreamer/bin/python"
./scripts/python.sh scripts/collect-vision.py --output work/m72/dataset-1
./scripts/python.sh scripts/train-vision.py --dataset work/m72/dataset-1 --output work/m72/train-1 --device mps
./scripts/python.sh scripts/evaluate-vision.py --dataset work/m72/dataset-1 --checkpoint work/m72/train-1/model.pt --output work/m72/offline-1
./scripts/python.sh scripts/run-camera-pilot.py --count 12 --vision-checkpoint work/m72/train-1/model.pt --output work/m72/pilot-12
```

Use fresh output directories. Native rendering requires a graphics-capable
process; training explicitly errors if the requested MPS device is unavailable.
The CPU inference path is the initial closed-loop configuration. Manifests record
dataset and checkpoint hashes. Full sequences and trajectories remain in ignored
`work/m72`; generated data and third-party environments are not committed.

## Results

The first 40-sequence collection completed: 5,120 frames, 24 training scenes,
8 validation scenes and 8 development scenes. Two networks contain 60,180 total
parameters. MPS training completed 1,500 steps in 51.3 seconds; validation selected
step 700 with a 0.98 floor threshold. The first native pilot reached **0/12** goals
with no collisions: every case stopped because no route was available.

Two deployment problems emerged. Native upsampling and the conservative reduced
floor labels changed the recall/false-free tradeoff. Recalibrating the threshold
on the eight native validation snapshots chose 0.5, but another 12-case pilot
still reached **0/12**. Inspecting the actual grid cells showed BB-8's own start
was blocked in every case: the network had learned to classify the robot as a
non-floor object, and its prediction extended beyond the existing RGB self-mask.

The corrective experiment re-renders the same 40 scenes with 16 frames at an
eight-action spacing (640 images, not 40 additional independent scenes). The
renderer now also supplies exact visible body/head labels. The new traversability
target is visible floor **or visible self**, so the robot does not obstruct its
own plan. Occluding obstacles are not relabeled. The previously trained head
network is frozen while the floor network is trained from scratch. Native
validation threshold selection precedes the next offline and closed-loop audits.
Visible self pixels receive 100× loss weight because they cover only a few
reduced-resolution pixels but can block the entire route. Selection adds
`2*self_pixel_miss_fraction` to the original criterion. The native validation
calibrator includes the same self-miss penalty for the corrected checkpoint.

```bash
./scripts/python.sh scripts/collect-vision.py --output work/m72/dataset-2 --frames 16 --frame-stride 8
./scripts/python.sh scripts/train-vision.py --dataset work/m72/dataset-2 --output work/m72/train-2 --floor-target traversable --head-checkpoint work/m72/train-1/model.pt --freeze-head --device mps
./scripts/python.sh scripts/calibrate-vision.py --dataset work/m72/dataset-2 --checkpoint work/m72/train-2/model.pt --output work/m72/calibrated-2
./scripts/python.sh scripts/evaluate-vision.py --dataset work/m72/dataset-2 --checkpoint work/m72/calibrated-2/model.pt --output work/m72/offline-2
./scripts/python.sh scripts/run-camera-pilot.py --count 12 --vision-checkpoint work/m72/calibrated-2/model.pt --output work/m72/pilot-2-12
```

The corrective training completed in 36.1 seconds on MPS. Validation selected
step 1,500; native validation selected a 0.5 threshold. The frozen head weights
were preserved exactly. All failed attempts are retained.

| Observer / development run | Arrivals | Map/route aborts | Collisions |
| --- | ---: | ---: | ---: |
| M7.1 palette | 1/12 | 11 | 0 |
| First learned floor/head | 0/12 | 12 | 0 |
| Same weights, native threshold refinement | 0/12 | 12 | 0 |
| Corrected floor/self labels and loss | **6/12** | 6 | 0 |

Successful corrected cases are 001, 002, 004, 005, 006 and 010. The original
10 cm / 3 cm/s / 0.5 s arrival condition is unchanged. These are repeated,
previously inspected development cases, not 48 independent trials or held-out
acceptance. The observed gain is an engineering result for this one seed; data
cadence, target labels and loss changed together, so it is not a controlled
single-factor ablation or a claim of algorithmic superiority.

On the eight development snapshots, averaging scene-wise metrics, false-free
blocked pixels fell from 7.881% for the palette classifier to 0.279% for the
corrected network. Floor recall fell from 99.668% to 96.344%, and floor IoU fell
from 98.714% to 96.303%. Visible self pixels are excluded from this floor-only
comparison. Both methods use identical images and label masks. Head localization
was available on all eight snapshots, with errors 4.45–10.57 mm. Stored crop
metrics are conditional on the RGB proposals and do not measure full-frame
detector recall; some scenes have no positive crops among the first six proposals.

Across the corrected closed-loop cases, localization error p95 was 3.16–10.05 mm.
CPU observer+policy p95 ranged 22.3–36.1 ms; observer+physics+render cycle p95 ranged
42.9–60.6 ms. The requested 20 Hz simulation action cadence therefore does not
establish sustained 20 Hz real-camera operation. These timings exclude startup
and physical camera capture/transport.

A matched rerun of case 002 injected five blank frames at action 80. All five
commands were zero; tracking resumed and the robot arrived at 13.35 simulated
seconds, versus 13.10 without dropout. Final distance was 3.10 cm, speed
0.00774 m/s and dwell 0.515 seconds. This single dropout test is separate from
the 12-case denominator.

55 non-GUI tests passed; lint, compilation and touched-file formatting passed.
Native collection, both training attempts, all three learned pilots and the
dropout run completed. Genesis Studio remained clean and the actuation adapter's
SHA-256 matched the previous M7.1 source archive.

## Next experiment

1. Instrument the six map failures at the actual stop frame. Cases 000/003/009
   have blocked goal cells initially; 000/007 have blocked estimated start cells.
   Case 011 has free endpoint cells but cannot connect the exact endpoints safely
   to the grid. Case 008 travels for 14 seconds before route loss. Distinguish
   genuine visual occlusion, classifier errors, self-mask errors and discretization
   using renderer truth only in the scorer; do not clear cells from that truth.
2. Refine map boundaries at native resolution and validate losses in the projected
   occupancy grid. Compare the current map with a causal temporal map, preserving
   unknown regions and stale-observation braking. Keep the SAC weights fixed.
3. Train/compare the planned temporal localization/visibility/uncertainty student,
   remove dependence on gray crop proposals, and add real distractors, texture and
   blur variation. Use reviewed SAM labels when checkpoint/runtime access is ready;
   compare the causal TAPNext pipeline separately rather than claiming it ran here.
4. Repeat the chosen configuration with three seeds, then freeze a fresh suite
   of unseen rooms/cameras. Record navigation success, collisions, false-free map
   cells, dropout/occlusion recovery and wall-clock latency before a hardware stage.
   A 6/12 development result does not meet an almost-always-reaching target.
