# SAC and DreamerV3 comparison

The [M5 protocol](M5_PLAN.md) defines a state-observation comparison in the
synthetic room. Dreamer uses the authors' code, pinned to commit
`e3f02248693a79dc8b0ebd62c93683888ddaccfe`; the upstream tree is not modified.

## Setup and commands

Run from BB8-RL with the existing native simulation runtime available:

```bash
bash scripts/setup-dreamer.sh
export BB8_PYTHON="$PWD/.venv-dreamer/bin/python"
./scripts/run-bb8.sh train --config configs/training/sac-m5.yaml --output work/my-sac
./scripts/run-bb8.sh train-dreamer --config configs/training/dreamer-m5.yaml --output work/my-dreamer
```

The isolated overlay links to the existing simulation packages and installs its
own CPU JAX/NumPy dependencies. It is local-machine configuration, not a portable
environment archive. Both M5 learners use this overlay, controlling the NumPy and
physics dependency versions as well as the task. No packages are installed into
Studio's runtime. The CPU requirements are a tested subset of upstream: no Atari,
Minecraft, CUDA, or external logging accounts are required. Network access is
needed once to obtain code and packages.

The legacy machine manifest inventories distributions from both the overlay and
its inherited package directory; duplicate package names may show the inherited
version. Use `selected_runtime_versions` in new pilot manifests, or the delivered
`runtime-proof.json`, for versions selected by Python. The latter also records
the imported NumPy/OpenCV module paths. This distinction does not affect model
execution; both learners run with the same explicitly selected interpreter.

Read each run's `latest.json` for the actual checkpoint directory. Evaluation:

```bash
./scripts/run-bb8.sh evaluate --task projects/bb8/synthetic-room/task-penalty-v2.yaml --episodes 12 --controllers dreamerv3 --checkpoint CHECKPOINT_DIRECTORY --output work/my-dreamer-eval
./scripts/run-bb8.sh evaluate --task projects/bb8/synthetic-room/task-penalty-v2.yaml --episodes 12 --controllers sac-her --checkpoint SAC_CHECKPOINT_DIRECTORY --output work/my-sac-eval
```

For a relocated checkout, set `BB8_DREAMER_ROOT` to the pinned upstream directory.
Checks reject changed upstream code and mismatched task/world contracts.

## Adapter contract

Dreamer consumes exactly the feature extractor used by SAC: scaled state/history,
average-pooled local map, and relative goal. Dreamer additionally maintains its
own recurrent latent state. The state/map is oracle data, not camera perception.

Upstream Driver determines action/observation alignment. Resets produce
`is_first=True` with zero reward; they are retained in sequential replay but do not
count toward the physical action budget. Collision/boundary failure sets both
`is_terminal` and `is_last`; timeout sets only `is_last`. Training continues after
arrival, as in SAC. Evaluation ends after arrival dwell or episode failure/timeout.

The size1m preset is used without the tiny upstream debug model. The resolved
architecture, float32 CPU platform, horizon 50, batches and replay ratio are saved
in `agent-config.yaml`. The resource-bounded pilot uses a lower replay ratio than
upstream's continuous-control benchmark recipe. This comparison is not an attempt
to reproduce the paper's benchmark scores. Startup/JIT costs are included in wall
time; gradient time includes the first training compilation.

Upstream Dreamer samples its actions in `mode='eval'` too. This behavior is retained
and labeled; the action RNG counter is set from each validation case's seed and
the recurrent state is cleared for each case. SAC evaluation uses deterministic
actions. Dreamer checkpoint reload reproduces the same seeded policy trace within
the tested runtime; no cross-platform bitwise claim is made.

## Evidence and checkpoints

Runs contain a machine/package/source manifest, episodes, scalar losses, replay
chunks, resolved configuration, and atomically published checkpoint directories.
Each Dreamer checkpoint stores trusted local `agent.pkl` (parameters, optimizer
state and counters) plus `state.json` with checksum and task/upstream/source
provenance. Checksums are verified before loading. Replay is saved separately in
the run directory. Exact Dreamer training continuation is not implemented: the
saved recurrent trainer carry, stream/sampler state and physics state would also
need a defined restoration contract. Use fresh runs for this pilot. SAC's existing
episode-boundary resume remains available.

First SIGINT/SIGTERM finishes the current episode, saves, and reports cancellation;
a second interrupt exits immediately, preserving the last complete checkpoint.
Failure/cancellation manifests remain distinct from completed training.

Read the measured report before interpreting a model as useful navigation. A*
has full map access, whereas both learners have a local map; it is a reference,
not an equal-information competitor. The final test suite remains reserved.

## Measured pilot, 16 September 2026

The accepted fresh runs completed 30,285 SAC actions (29,085 updates, 286.0 s)
and 31,019 Dreamer actions (3,690 sequence updates, 412.7 s). On the same 12
validation cases, SAC achieved 0 arrivals, 3 contact episodes and 9 timeouts;
Dreamer achieved 0 arrivals, 11 contact episodes and 1 timeout. The full-map A*
reference achieved 12/12 arrivals with no contacts. Neither learner recorded a
training arrival. The final test suite remains unused.

Dreamer did not demonstrate a navigation benefit in this bounded pilot. Fewer
contacts for SAC do not establish successful navigation, and these results do not
rank the algorithms generally. A useful next experiment is an easier short-range
curriculum and/or A* demonstrations with sufficient student observations, before
scaling either model or moving to camera input.

Verification: 43 non-GUI tests and 8 targeted native Genesis/SAC tests passed;
the final Dreamer checkpoint restored matching parameters/optimizer tensors and
reproduced an eight-action seeded inference trace. Final dependency checks found
no broken requirements. Raw results are in `work/m5/comparison-final`, with the
generated comparison and paths in `work/m5/summary`.
